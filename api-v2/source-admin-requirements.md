# 혼잡도

## 대운동장 혼잡도 조회 및 변경

# ADM-CROWD-001 · 재학생존 혼잡도 관리

| 항목 | 명세 내용 |
| --- | --- |
| 기능 ID | ADM-CROWD-001 |
| 기능명 | 재학생존 혼잡도 관리 |
| 기능 목적 | 관리자가 대운동장 재학생존의 현재 혼잡 상태를 확인·변경하고 저장 결과를 관련 사용자 기능에 반영 |
| 진입 경로 | 관리자 웹페이지 → 대운동장 혼잡도 관리 |
| 사용 대상과 권한 | 관리자 페이지 접근 권한이 있는 총학생회 현장 운영자 |
| 실행 조건 | 해당 운영일에 적용할 운영 시간이 존재하고 관리자가 관리자 페이지에 접근 가능한 상태 / 별도 운영 시간 설정이 없으면 기본값 `13:00~22:00` 적용 |
| 관리 상태 | `여유 / 보통 / 혼잡 / 만석` |
| 관련 기능 | ADM-CROWD-002 재학생존 운영 시간 관리 / HOME-001 재학생존 혼잡도 확인 / MAP-001 지도 혼잡도 표시 |

### 1. 관리자 확인 정보

| 항목 | 규칙 |
| --- | --- |
| 현재 혼잡도 | 서버에 최종 저장된 혼잡도 표시 |
| 상태 선택 | `여유 / 보통 / 혼잡 / 만석` 중 현재 상태 확인 및 변경 가능 |
| 최종 수정 시각 | 가장 최근 혼잡도 변경 저장 성공 시각 표시 |
| 최초 수정 전 | `운영 시작 기준` 표시 |
| 운영 상태 | 현재 운영 시간에 따라 `운영 전 / 운영 중 / 운영 종료` 확인 |

### 2. 혼잡도 단계 및 판단 기준

| 상태 | 운영자 판단 기준 |
| --- | --- |
| 여유 | 공간 점유율 추정치 50% 이하 |
| 보통 | 공간 점유율 추정치 50% 초과~70% 이하 |
| 혼잡 | 공간 점유율 추정치 70% 초과~추가 입장 통제 전 |
| 만석 | 재학생존 추가 입장 통제 시작 |

| 항목 | 규칙 |
| --- | --- |
| 판단 방식 | 실제 입장 인원을 자동 집계하지 않고 현장 운영자의 관찰을 기준으로 판단 |
| 퍼센트 기준 | 운영자의 상태 판단을 위한 내부 참고 기준 |
| 85% 기준 | 추가 입장 통제 여부를 판단하기 위한 참고 수준 |
| 만석 자동 처리 | 85% 도달만으로 자동 만석 처리하지 않음 |
| 만석 판단 | 실제 추가 입장 통제를 시작하는 시점에 관리자가 직접 `만석` 선택 |

### 3. 혼잡도 변경

| 순서 | 처리 |
| --- | --- |
| 1 | 현재 혼잡도와 최종 수정 시각 확인 |
| 2 | 변경할 상태 선택 |
| 3 | `여유 / 보통 / 혼잡` 선택 시 저장 요청 |
| 4 | `만석` 선택 시 확인창 표시 |
| 5 | 관리자가 변경 여부 최종 확인 |
| 6 | 서버에 상태 저장 |
| 7 | 저장 성공 시 현재 상태와 최종 수정 시각 갱신 |
| 8 | 저장 결과를 HOME-001 및 MAP-001에 반영 |

### 4. 상태 저장 규칙

| 항목 | 규칙 |
| --- | --- |
| 저장 방식 | 상태 선택을 저장 동작으로 처리 |
| 여유·보통·혼잡 | 선택 즉시 저장 요청 |
| 만석 | 확인 후 저장 요청 |
| 동일 상태 재선택 | 저장하지 않으며 최종 수정 시각도 갱신하지 않음 |
| 저장 중 추가 변경 | 기존 저장 요청 완료 전 추가 변경 제한 |
| 저장 성공 기준 | 서버 저장 성공 시 실제 변경 완료 |
| 데이터 기준 | 서버에 최종 저장된 상태 사용 |

### 5. 만석 확인

| 항목 | 내용 |
| --- | --- |
| 노출 조건 | 관리자가 `만석` 선택 |
| 확인 문구 | `재학생존을 만석으로 변경하시겠습니까?` |
| 확인 버튼 | `만석으로 변경` |
| 취소 버튼 | `취소` |
| 확인 | 만석 상태 저장 요청 |
| 취소 | 기존 상태 유지 |

### 6. 운영 시간 연동

| 상황 | 처리 |
| --- | --- |
| 입장 시작 전 | `운영 전` |
| 운영 시작 + 당일 수정 이력 없음 | `여유 / 운영 시작 기준` |
| 운영 중 관리자 변경 | 저장된 혼잡도 적용 |
| 운영 종료 이후 | `운영 종료` |
| 운영 종료 후 | 당일 마지막 혼잡도와 수정 시각 유지 |
| 운영 시간 연장 후 재개 | 당일 마지막 혼잡도와 수정 시각 복원 |
| 재개 + 수정 이력 없음 | `여유 / 운영 시작 기준` |
| 새로운 운영일 | 이전 운영일의 혼잡도와 수정 시각 미이월 |

`운영 전 / 운영 중 / 운영 종료` 판단은 ADM-CROWD-002에 저장된 운영 시간을 기준으로 시스템이 처리한다.

### 7. 운영 시간 변경 시 재적용

| 상황 | 처리 |
| --- | --- |
| ADM-CROWD-002 저장 성공 | 현재 시각과 변경된 운영 시간 재비교 |
| 시작 시각 이전 | `운영 전` |
| 운영 시간 내 | 당일 저장 혼잡도 적용 |
| 종료 시각 이후 | `운영 종료` |
| 운영 시간 내 재진입 + 수정 이력 있음 | 마지막 혼잡도와 수정 시각 복원 |
| 운영 시간 내 재진입 + 수정 이력 없음 | `여유 / 운영 시작 기준` |

### 8. 최종 수정 시각

| 항목 | 규칙 |
| --- | --- |
| 생성 기준 | 혼잡도 변경 서버 저장 성공 시각 |
| 시간 기준 | KST(Asia/Seoul) |
| 갱신 조건 | 기존 상태와 다른 혼잡도 저장 성공 |
| 동일 상태 | 갱신하지 않음 |
| 저장 실패 | 기존 시각 유지 |

| 운영 재개 | 당일 수정 이력이 있으면 기존 시각 복원 |

| 저장 실패 | 실패한 변경값은 관련 사용자 기능에 반영하지 않음 |

혼잡도에 따른 색상, 상태별 안내 문구, 화면 표시 및 사용자 동작은 HOME-001과 MAP-001에서 정의한다.

| 관리자 화면 | 서버 최신 상태 및 수정 시각 기준 |

## 대운동장 운영 시간 관리

# ADM-CROWD-002 · 재학생존 운영 시간 관리

| 항목 | 명세 내용 |
| --- | --- |
| 기능 ID | ADM-CROWD-002 |
| 기능명 | 재학생존 운영 시간 관리 |
| 기능 목적 | 관리자가 운영일별 재학생존 입장 시작 및 운영 종료 시각을 확인·수정하고 저장된 운영 시간을 혼잡도 상태 판단에 반영 |
| 진입 경로 | 관리자 웹페이지 → 대운동장 혼잡도 관리 → 운영 시간 설정 |
| 사용 대상과 권한 | 관리자 페이지 접근 권한이 있는 총학생회 운영자 |
| 관리 단위 | 축제 운영일별 입장 시작·운영 종료 시각 |
| 기본 시작 시각 | 13:00 |
| 기본 종료 시각 | 22:00 |
| 관련 기능 | ADM-CROWD-001 / HOME-001 / MAP-001 |

### 1. 관리자 확인 및 입력 정보

| 항목 | 규칙 |
| --- | --- |
| 운영일 | 축제 운영 날짜 표시 |
| 입장 시작 시각 | 해당 날짜의 저장된 입장 시작 시각 표시 및 수정 |
| 운영 종료 시각 | 해당 날짜의 저장된 종료 시각 표시 및 수정 |
| 시간 형식 | `HH:mm` |
| 날짜별 관리 | 각 운영일 독립 관리 |
| 기본값 | 별도 설정이 없는 경우 `13:00~22:00` |

공연 시간 및 타임테이블은 본 기능에서 관리하지 않는다.

### 2. 운영 시간 변경

| 순서 | 처리 |
| --- | --- |
| 1 | 수정할 운영일 확인 |
| 2 | 현재 시작·종료 시각 확인 |
| 3 | 필요한 시간 변경 |
| 4 | `저장` 선택 |
| 5 | 입력값 검증 |
| 6 | 서버에 운영 시간 저장 |
| 7 | 저장 성공 시 해당 운영일 시간 갱신 |
| 8 | 현재 운영일인 경우 현재 시각과 운영 시간 재비교 |
| 9 | 운영 상태 재판정 |
| 10 | ADM-CROWD-001 및 관련 사용자 기능에 변경된 운영 시간 반영 |

### 3. 입력 및 저장 규칙

| 항목 | 규칙 |
| --- | --- |
| 입장 시작 시각 | 필수 |
| 운영 종료 시각 | 필수 |
| 시간 관계 | 종료 시각은 시작 시각보다 이후 |
| 저장 방식 | `저장` 선택 후 변경 적용 |
| 저장 기준 | 서버 저장 성공 시 완료 |
| 날짜별 독립성 | 다른 운영일 설정에 영향 없음 |
| 저장 전 변경 | 실제 운영 상태에 미반영 |

### 4. 운영 상태 자동 판단

| 현재 시각 | 상태 |
| --- | --- |
| 입장 시작 이전 | `운영 전` |
| 시작~종료 사이 | `운영 중` |
| 운영 종료 이후 | `운영 종료` |

운영 상태는 관리자가 직접 선택하지 않는다.

### 5. 운영 시간 변경에 따른 처리

| 상황 | 처리 |
| --- | --- |
| 종료 시각을 현재 이전으로 변경 | 저장 성공 후 `운영 종료` |
| 종료 후 종료 시각 연장 | 현재 시각이 운영 범위에 포함되면 `운영 중` |
| 운영 재개 + 당일 혼잡도 이력 있음 | ADM-CROWD-001의 마지막 혼잡도 및 수정 시각 복원 |
| 운영 재개 + 이력 없음 | `여유 / 운영 시작 기준` |
| 시작 시각을 현재보다 이후로 변경 | `운영 전` |
| 새로운 운영일 | 이전 날짜 혼잡도 및 수정 시각 미이월 |

### 6. 기능 연동

| 항목 | 규칙 |
| --- | --- |
| 반영 조건 | 운영 시간 저장 성공 |
| 전달 데이터 | 해당 운영일의 입장 시작 시각 / 운영 종료 시각 |
| 관리자 연동 | ADM-CROWD-001의 운영 상태 판단에 사용 |
| 사용자 기능 연동 | HOME-001 및 MAP-001의 운영 상태 판단에 사용 |
| 데이터 기준 | 서버에 최종 저장된 운영 시간 |
| 저장 실패 | 변경된 운영 시간을 관련 기능에 반영하지 않음 |

사용자 화면의 운영 전·중·종료 표현 및 안내 문구는 HOME-001과 MAP-001에서 정의한다.

### 7. 예외 상황 및 오류 처리

| 상황 | 대응 |
| --- | --- |
| 시작 시각 미입력 | 저장하지 않고 필수 입력 안내 |
| 종료 시각 미입력 | 저장하지 않고 필수 입력 안내 |
| 종료 시각 ≤ 시작 시각 | 저장하지 않고 시간 오류 안내 |
| 저장 실패 | 기존 운영 시간 유지 |
| 저장 실패 영향 | 기존 운영 시간을 기준으로 상태 유지 |
| 오류 메시지 | `운영 시간을 저장하지 못했습니다. 다시 시도해주세요.` |
| 운영 시간 미설정 | 기본값 `13:00~22:00` 적용 |
| 재시도 | 오류 확인 후 다시 저장 가능 |

### 8. 완료 기준

| 확인 항목 | 완료 기준 |
| --- | --- |
| 조회 | 운영일별 시작·종료 시각 확인 가능 |

## 6. 사용자 노출 대상 판정 규칙

| --- | --- |

| 일반 공지 날짜 변경 | KST 00:00 이후 전날 등록 일반 공지는 노출 대상에서 제외 |

| 삭제된 공지 | 사용자 노출 대상에서 제외 |

노출 여부는 관리자 화면에서 별도의 `노출/비노출` 버튼으로 직접 선택하는 방식이 아니라 **저장된 공지 유형·등록 시간·번역 상태·삭제 상태를 기준으로 시스템이 판정**한다.

| 공지 삭제 | 삭제 성공 후 남은 공지를 기준으로 최신 공지 재판정 |
| 날짜 변경 | KST 00:00 기준으로 일반 공지 대상 재판정 |

HOME-003에서 제목을 어떻게 표시하거나 사용자가 어떻게 진입하는지는 HOME-003 명세에서 정의한다.

## 1. 삭제 처리

| 순서 | 처리 |

| 9 | 최신 관리자 목록 재조회 |

## 1. 재고 확인

| 항목 | 규칙 |
| --- | --- |
| 상품 구분 | 등록된 굿즈별로 재고 정보를 구분하여 표시 |
| 색상 구분 | 상품에 등록된 색상별로 영역 구분 |
| 사이즈 표시 | 각 색상에 등록된 판매 사이즈 표시 |
| 표시 정보 | 상품명 / 색상 / 사이즈 / 남은 재고 수량 / 재고 상태 |
| 재고 수량 | 각 색상·사이즈 조합별 서버에 저장된 현재 남은 수량 표시 |
| 재고 상태 | 저장된 수량을 기준으로 `구매 가능 / 품절` 자동 표시 |

관리자는 **상품 → 색상 → 사이즈 → 남은 재고 수량** 순서로 재고를 확인한다.

## 2. 재고 수량 변경

| 순서 | 처리 |
| --- | --- |
| 1 | 관리자가 재고를 수정할 상품 확인 |
| 2 | 해당 상품의 색상 확인 |
| 3 | 색상별 사이즈와 현재 재고 수량 확인 |
| 4 | 변경할 색상·사이즈의 남은 수량 입력 |
| 5 | `저장` 선택 |
| 6 | 입력값 검증 |
| 7 | 서버에 변경된 재고 수량 저장 |
| 8 | 저장 성공 시 해당 색상·사이즈 재고 수량 갱신 |
| 9 | 저장된 수량을 기준으로 재고 상태 자동 재판정 |
| 10 | 저장 결과를 GOODS-001에 반영 |

## 3. 재고 수량 입력 규칙

| 항목 | 규칙 |
| --- | --- |
| 입력 단위 | 상품의 색상 × 사이즈 조합별 개별 입력 |
| 입력값 | `0 이상의 정수` |
| 음수 | 입력 불가 |
| 소수 | 입력 불가 |
| 구매 가능 기준 | 남은 수량 `1개 이상` |
| 품절 기준 | 남은 수량 `0개` |
| 품절 처리 | 수량이 `0`이 되면 자동으로 품절 판정 |
| 품절 해제 | 수량이 `1개 이상`이 되면 자동으로 구매 가능 판정 |
| 사이즈별 관리 | 같은 색상에서도 각 사이즈를 독립적인 재고로 관리 |
| 색상별 관리 | 동일 사이즈라도 색상이 다르면 별도 재고로 관리 |
| 상품 간 관리 | 한 상품의 재고 변경은 다른 상품에 영향 없음 |

`구매 가능 / 품절`은 관리자가 직접 선택하는 값이 아니라 **서버에 저장된 재고 수량을 기준으로 자동 결정되는 상태**이다.

## 4. 재고 상태 자동 판정

| 상황 | 시스템 처리 |
| --- | --- |
| 특정 색상·사이즈 재고 `1개 이상` | 해당 조합을 `구매 가능` 상태로 판정 |
| 특정 색상·사이즈 재고 `0개` | 해당 조합을 `품절` 상태로 판정 |
| 한 색상의 일부 사이즈만 `0개` | 해당 사이즈만 품절 판정 |
| 한 색상의 모든 사이즈가 `0개` | 해당 색상에 속한 모든 사이즈를 각각 품절 판정 |
| 일부 색상·사이즈에 재고 존재 | 상품 전체는 전체 품절로 판정하지 않음 |
| 모든 색상·사이즈 재고 `0개` | 상품을 삭제하지 않고 `전체 품절` 상태로 판정 |

별도의 `색상 품절` 상태는 관리하지 않는다. 재고 상태는 색상×사이즈 조합별로 판정한다.

## 5. 신규 상품·옵션 초기 재고

| 상황 | 처리 |
| --- | --- |
| 신규 상품 등록 | 등록된 색상×사이즈 조합별 재고 관리 항목 생성 |
| 신규 상품 초기 재고 | 각 색상×사이즈 조합을 `0개`로 생성 |
| 기존 상품에 새 색상 추가 | 새 색상과 기존 사이즈의 조합별 재고를 `0개`로 생성 |
| 기존 상품에 새 사이즈 추가 | 기존 색상과 새 사이즈의 조합별 재고를 `0개`로 생성 |
| 초기 상태 | 재고 `0개`이므로 해당 조합은 품절 상태로 판정 |
| 재고 입력 | 관리자가 실제 수량 확인 후 필요한 조합의 수량 수정 |

신규 상품이나 옵션을 등록한 것만으로 구매 가능한 상태가 되지 않는다.

## 10. ADM-GOODS-001 재고 관리 연동

`ADM-GOODS-002`는 **무엇을 판매하는지**를 관리하고, `ADM-GOODS-001`은 **각 색상×사이즈 조합의 실제 재고가 몇 개 남았는지**를 관리한다.

| 관리 대상 | 담당 기능 |
| --- | --- |
| 상품명 | ADM-GOODS-002 |
| 가격 | ADM-GOODS-002 |
| 상품 이미지 | ADM-GOODS-002 |
| 제공 색상 | ADM-GOODS-002 |
| 제공 사이즈 | ADM-GOODS-002 |
| 색상×사이즈별 남은 재고 수량 | ADM-GOODS-001 |
| 구매 가능·품절 판정 | ADM-GOODS-001 |
| 전체 품절 판정 | ADM-GOODS-001 |

신규 상품이나 새로운 색상·사이즈가 저장되면 ADM-GOODS-001에 해당 색상×사이즈 조합을 생성하고 초기 재고는 `0개`로 설정한다.
