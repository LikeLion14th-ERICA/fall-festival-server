# API v2 결정 대기와 자료 요청

[관리자 v5](../docs/wiki/product/admin/README.md)와 2026-09-14 사용자 결정을 기준으로 합니다.
운영 시간은 개발자 등록, 굿즈 수량 미관리, 한국어 우선 게시는 확정입니다. 아래 기술 초안과
운영 자료는 별도 합의가 필요하며 목 응답이 운영 승인을 의미하지 않습니다. 과거 질문 ID는
원문 스냅샷에만 보존하며 현재 판단은 위키와 이 문서를 따릅니다.

| 기술 계약 초안 | 답변할 질문 | 현재 상태·목 처리 |
|---|---|---|
| 관리자 인증 | 확정: username 로그인, 단일 ADMIN, 15분 signed JWT access token, 7일 opaque refresh cookie와 rotation/revoke | 목은 실제 자격증명 대신 `MOCK-*` 값만 사용. 공개 회원가입·세부 RBAC 없음 |
| 적용 API 버전 | API v2만 제품 계약으로 사용한다. | 이전 제품 계약·경로는 폐기했다. 공개 카탈로그(`spaces`, `maps`, `places`, ticket guide의 `mapTarget`)는 Spring·Flyway 구현과 계약 검증을 마쳤고, 나머지 화면 연동 목·관리 쓰기 경로의 실제 배포 범위와 migration은 계속 추적한다. |
| 콘텐츠 revision | 축제 revision을 snapshot·행 버전·게시 이력 중 어떤 단위로 저장하고 rollback할까요? | 개발자 전용 CLI가 완전 JSON revision을 import·validate·publish·rollback한다. published snapshot은 단일 인스턴스의 제어된 재시작으로 반영하며, 다중 인스턴스 전파와 CDN은 도입 뒤 재평가한다. |
| 카탈로그 locale | 어떤 언어를 공개하고 번역 누락을 어떻게 처리할까요? | 한국어만 현재 READY다. 승인·검수까지 끝난 언어만 locale 목록에 추가하며, 공간·장소·지도·핀·필터 label·정렬이 모두 준비되지 않으면 공개하지 않는다. fallback은 없다. |
| Current Festival context | 어떤 축제 회차를 제공할지 서버가 어떻게 결정할까요? | `FESTIVAL_ID` 환경변수의 UUID로 명시한다. DB의 첫 행·최대 revision·최근 게시 시각으로 추측하지 않는다. 설정된 회차의 published revision에 안전하게 귀속되지 않는 응답의 `meta.revision`은 0이다. |
| 공지 입력·번역 기술 | 길이 제한·번역 엔진·원문 갱신 확인 방식을 확정할 수 있나요? | 한국어 READY만 필수. 미완료/실패 언어는 미노출. 길이 제한·미리보기 source 비교는 기술 초안 |
| 갱신 방식 | 새로고침 없는 반영의 통신 방식과 최대 지연을 어떻게 정할까요? | 화면이 보이는 동안 15초 HTTP polling을 쓴다. 진입·재활성화·온라인 복귀는 즉시 조회하고, 숨김·오프라인은 중단한다. 30초·60초 backoff, 요청 중복 방지, 늦은 응답 폐기를 적용한다. |
| 혼잡도 동일 상태 재선택 | 같은 상태를 다시 선택할 때 저장·수정 시각을 갱신할까요? | 성공으로 응답하지만 저장·수정 시각은 유지한다. |
| 신규 옵션 최초 상태 | 등록 시 구매 가능/품절을 누가 언제 지정하나요? | 신규 상품·조합은 `ON_SALE`로 생성한다. |
| 운영일 밖 혼잡도 저장 | 실제 축제 운영일이 아닌 날짜에도 단계 선택을 허용하나요? | 허용하지 않는다. PUT 대상 날짜가 published `FestivalDay`가 아니면 `409 NOT_FESTIVAL_DAY`로 거절한다. 실제 `FestivalDay`인 날짜는 운영 전·운영 종료 뒤에도 저장할 수 있으며, 공개 홈은 실제 운영 시간 상태를 우선하고 저장 시각을 숨긴다. |
| 상품 이미지·옵션 기술 | 이미지 개수·용량·업로드 방식, 옵션 ID 발급 주체와 옵션 없는 상품 입력 방식을 무엇으로 할까요? | 실제 색상·사이즈·조합은 비어 있지 않은 입력만 검증. 이미지 없는 저장은 409로 차단하고, 이미지 구성과 옵션 없는 상품 입력 방식은 미정 |
| 상품 색상·사이즈·조합 삭제 | 등록 후 색상·사이즈·제공 조합을 삭제할 수 있나요? | 삭제를 허용한다. 삭제한 조합의 판매 상태도 제거하고, 유지한 조합 상태는 보존하며 남은 조합으로 전체 품절을 다시 계산한다. |
| 지도 | 0~1 좌표·이미지 버전 일치 방식, 필터 분류, `PLACE`/`AREA` 핀 target의 DB XOR 제약을 어떻게 둘까요? | 정규화 좌표와 버전 불일치 409. `Pin.category`는 세부 종류로 유지하고 `filterGroup`과 현재 지도에 실제 있는 `filters`를 제공한다. 필터는 디자인의 화장실·포토부스·흡연구역·쓰레기통이며 그 밖의 `PLACE` 핀은 그룹 null로 `전체`에서만 보인다. `AREA`는 그룹 null이며 항상 표시한다. |
| 공연 무대 | 여러 무대 동시 공연을 위한 stage ID·명칭·지도 연결을 API v2에 추가할까요? | 단일 무대만 사용한다. `Performance.stage`와 `Stage` 모델은 추가하지 않는다. |
| 상품 정렬 | 상품의 편집 가능한 표시 순서가 필요한가요? | 상품은 등록 순서 초안. 공간 가나다순·별 우선, 라인업 공연 순서는 위키 확정 |
| QR 안내 | 공통 QR 값은 누가 발급·교체하고 어느 경로로 배포하나요? | 안내 응답에 가상 QR 자료. 서버 참여 인증으로 사용하지 않음 |
| 스탬프 수령 인증 코드 | 수령 인증 코드의 발급·안전한 전달·교체 담당자와 당일 유효 기간은 무엇인가요? | 공개 `POST /stamp-receipt-verifications`는 현장 담당자가 입력한 코드만 서버에서 확인하고 `verified: true`만 반환한다. 실제 값은 서버 비밀 설정으로만 관리하며 사용자 참여·지급 이력은 만들지 않는다. |
| 미설정 UI | 필수 운영 자료를 받기 전 노출 범위와 안내 화면은 어떻게 할까요? | 티켓 UNCONFIGURED, 웰컴·FAQ 링크 null, 선택 영역 숨김. 임의 공개 금지 |

아래는 총학생회에 전달할 수 있는 통합 질문입니다. **미정이면 담당자와 답변·자료 전달 예정일을 함께 적어 주세요.** 같은 담당자가 여러 업무를 맡는 경우 한 번에 답해도 됩니다.

1. **축제 일정과 입장 시간을 알려주세요.** 날짜별 공연 순서·시작/종료 시각, 재학생존 입장 시작/마감 시각이 필요합니다. 일정 변경을 앱 담당자에게 전달할 담당자와 연락 방법도 부탁드립니다.
2. **외부인 티켓의 가격과 운영 방식을 알려주세요.** 1인 가격, 송금 가능 시간, 수령·입장 시간, 은행·계좌·예금주, 티켓존 위치를 부탁드립니다. 선송금·여러 명 합산 송금은 무엇을 확인하고 몇 장을 지급하나요? 당일 사용 원칙과 미사용·공연 취소 시 환불 기준도 필요합니다.
3. **굿즈 최종 자료와 품절 대응 방식을 알려주세요.** 상품별 이름·가격·색상·사이즈·사진, 판매 장소·시간·송금 계좌를 부탁드립니다. 실제 제공하는 색상×사이즈 조합과 판매 상태를 갱신할 담당자를 알려주세요. 신규 조합은 구매 가능으로 시작하며, 선송금 후 품절 시 상품 변경·환불은 어떻게 처리하나요? 앱에서는 실제 수량을 관리하지 않습니다.
4. **혼잡도와 공지 운영 담당자는 누구인가요?** 혼잡도 단계별 판단 기준, 현장에서 직접 갱신할 수 있는지, 공지 등록 담당자를 알려주세요. 사전 번역할 주요 공지와 공식 운영 수칙도 부탁드립니다.
5. **참여 공간과 올해 최종 배치도를 보내주세요.** 부스·주점·플리마켓별 이름·사진·위치·운영 시간·소개, 주점 메뉴·가격, 부스 체험·이벤트가 필요합니다. 무대·게이트·티켓존·편의시설 위치도 표시해 주세요. 포토부스·피크닉존 운영 여부와 발전협력팀 세 칸이 하나의 부스인지 확인 부탁드립니다.
6. **스탬프 참여 부스와 상품 지급 기준을 알려주세요.** 체험 완료자에게 현장에서 공통 QR을 보여줄 수 있나요? 몬스터의 1회 지급 수량, 날짜별 준비 수량, 수령 장소·시간·담당자를 알려주세요. 수령 인증 코드는 멋사 부스 담당자가 사용자 휴대폰에 직접 입력하므로, 코드의 발급·안전한 전달·교체 담당자와 당일 유효 기간도 부탁드립니다. 실제 코드값은 이 문서나 앱에 넣지 않습니다.
7. **출연진 자료와 공식 연결 주소를 보내주세요.** 최종 출연진 이름·사진·소개·SNS, 정보 공개 가능 시점, 공식 채널 변경 여부를 부탁드립니다. 공식 채널은 홈 위키의 Instagram·YouTube·총학생회 홈페이지로 확정되어 있습니다.
8. **에리카 웰컴 데이 자료를 제공할 기관·담당자는 누구인가요?** 입학처에서는 전달 사항이 없다는 답변을 받은 상태입니다. 실제 제공 주체, 제공 가능 여부·전달 예정일, 자료 형태(이미지/PDF/텍스트/기존 웹페이지), 외부 소개 페이지로 공개 가능한지 확인 부탁드립니다. 행사 소개·일정·집결 장소·참여 방법도 필요합니다. 앱 홈에서는 준비된 외부 페이지를 새 탭으로 연결할 예정입니다.
9. **FAQ 외부 페이지 URL을 알려주세요.** 앱은 FAQ 버튼에서 승인된 HTTPS URL을 새 탭으로 연결합니다. 실제 제공 담당자, URL, 로그인 없는 접근 가능 여부와 모바일 가독성 확인 결과를 부탁드립니다. FAQ 내용·분류·번역은 외부 페이지 담당 범위입니다.

운영팀에 함께 전달할 내용:

- 티켓·굿즈 입금과 지급 여부는 현장 담당자가 직접 확인합니다.
- 굿즈를 현장 송금으로 안내해도 선송금이 가능하므로 품절 환불 대응이 필요합니다.
- 혼잡도·판매 상태는 담당자의 갱신 시점에 따라 실제 현장과 다를 수 있습니다.
- 공통 QR·로그인 없는 스탬프는 엄격한 중복 차단이 불가능하며 상품 소진은 현장 안내가 필요합니다.
- 스탬프 수령 인증 코드는 현장 담당자가 입력하고 서버에서만 검증합니다. 코드값은 화면·브라우저 저장소·로그에 남기지 않습니다.
