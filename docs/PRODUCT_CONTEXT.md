# 한양대학교 ERICA 가을 축제 웹 앱 — 제품 컨텍스트

이 문서는 실제 행사에서 운영되는 서비스의 제품 범위, 운영 기준, 근거 자료와 결정 대기
사항을 기록한다. 미결정 사항은 사실처럼 구현하거나 공개하지 않는다.

### 결정 우선순위

1. 사용자의 최신 명시적 결정
2. 총학생회·학교 승인 자료
3. Figma IA·와이어프레임
4. API v1 계약

예를 들어 FigJam은 챗봇을 전역 플로팅으로 표현하지만 최신 확정안은 홈에서
진입하도록 했다. 이 경우 홈 진입을 따른다. API v1은 상위 결정을 실행 가능한 계약으로
표현하며 충돌이 생기면 같은 변경에서 바로잡는다.

## 2. 제품 목적과 대상

- 한양대학교 ERICA 가을 축제의 현장 방문자가 행사 정보를 빠르고 정확하게 확인하는
  모바일 우선 웹 서비스
- 재학생뿐 아니라 외부 방문자, 고등학생 견학 방문자, 영어·중국어 사용자 지원
- 일반 사용자는 설치·로그인·회원가입 없이 공개 정보를 조회
- 혼잡한 행사장, 불안정한 모바일 네트워크, 운영 중 콘텐츠 변경과 트래픽 급증에서도
  핵심 정보 제공을 유지
- 핵심 과업:
  - 지금 진행 중인 공연·이벤트 확인
  - 시간과 장소 확인
  - 부스·주점·플리마켓 및 메뉴 확인
  - 지도에서 시설·부스 찾기
  - 최신 운영 공지 확인

FigJam 최상위에는 `학교 축제 PWA`라고 쓰여 있지만 설치 가능성, 오프라인 캐시,
푸시 알림의 제공 여부와 동작은 결정 대기다. 일반 웹 캐시와 장애 시 제한적 읽기 기능은
PWA 채택 여부와 별개의 운영 요구다.

## 3. 공개 사용자 IA

1. 홈
2. 라인업
3. 타임테이블
4. 부스 & 마켓

### 홈

- 현재 진행 중 공연·이벤트
- 공지사항 진입과 중요·긴급 공지 노출
- 챗봇 진입
- 언어 변경
- FUN·스탬프 투어가 채택될 경우의 진입점. 승인 전 카드나 placeholder도 공개하지 않음
- 고등학생 방문 안내: 총학생회 자료 수령 후 전용 route, modal, 홈 카드 중 형태와
  노출 조건을 확정

와이어프레임에는 FAQ, 분실물 안내, Instagram, YouTube, 에브리타임, 카카오톡
바로가기가 있으나 채널 구성과 제공 여부는 확정되지 않았다.

### 라인업

- 확정 목적: 축제 출연진 확인
- Figma 의도: 아티스트 검색, DAY 1/2/3, `전체 / 메인 아티스트 /
  동아리·콘테스트` 필터, 3열 카드
- 아티스트 상세에는 대표 이미지, 공연 일시·장소, SNS, 소개, 추천곡 3개,
  `내 일정에 추가`가 있다.
- 검색, 상세, 추천곡, `내 일정`, `동아리·콘테스트`의 공식 분류명은 Figma 제안이며
  구현 확정 전 확인한다.

### 타임테이블

- 현재 시각선 표시와 현재 공연 강조
- Figma 의도: 메인 스테이지, DAY 1/2/3 컬럼, 17:00–22:00, 30분 눈금
- FigJam에는 날짜별·무대별 일정과 공연 상세 Bottom Sheet가 함께 표현돼 있다.
- 실제 행사 일수, 무대 수, 공연 상세 동작, 동시 공연 표시 규칙은 운영 자료로 확정한다.
- 지연·취소·시간 변경과 마지막 갱신 시각을 사용자가 구분할 수 있어야 한다.

### 부스 & 마켓

- 카테고리: `전체 / 부스 / 플리마켓 / 주점`
- 목록 검색과 카드, 상세 화면, 지도 위치 연결
- 상세 의도: 대표 이미지, 운영 주체, 운영 시간, 위치, 문의, 소개, 메뉴·판매 품목,
  진행 이벤트, 스탬프 참여 여부
- 메뉴는 이미지에만 의존하지 않고 항목, 가격, 품절, 알레르기와 번역에 사용할 수 있는
  구조화 텍스트를 함께 제공한다. 제공·검수 주체와 필수 항목은 결정 대기다.

### 지도

- 축제 전용 일러스트 지도 위에 마커를 표시. 실제 지도 자산, 사용 권한, 수정 범위는
  운영 자료로 관리
- 구역 필터와 카테고리 필터
- 마커 선택 시 라벨 및 하단 바텀시트
- 바텀시트 의도: 아이콘, 카테고리, 이름, 운영 시간, 설명, 위치
- 부스 상세의 `지도에서 위치 보기`는 해당 마커로 이동
- 지도를 사용할 수 없는 이용자를 위해 동일 장소를 찾을 수 있는 목록·텍스트 경로 제공

공식 번역은 운영 자료 대기 항목이다.

## 6. 스탬프 투어 — 승인 전 구현하지 않음

와이어프레임 13–16은 다음 흐름을 제안한다.

`시작(1일 1회) → QR로 8개 스탬프 적립 → 기준 달성 → 룰렛 → 당첨 결과 → 수령 부스`

FigJam은 참여 등록에서 이름·전화번호·개인정보 동의를 수집하는 흐름도 제안한다.
이는 일반 사용자 비로그인 원칙 및 미성년자 가능성과 직접 관련되므로 승인된 요구사항이
아니다. 다음을 먼저 결정해야 한다.

- 참여자를 무엇으로 식별하는가
- 기기 변경·브라우저 데이터 삭제 시 복구하는가
- QR 유효성, 중복 적립, 부정 사용을 어떻게 막는가
- 1일 1회가 참여, 룰렛, 경품 수령 중 무엇에 적용되는가
- 개인정보를 수집하는가; 수집한다면 목적·보관·삭제·동의는 무엇인가
- 경품 재고, 당첨 확률, 수령 검증, 재응모·라운드 초기화 정책은 무엇인가

## 7. 익명 접근, 보안과 개인정보

- 라인업, 타임테이블, 부스, 지도, 공지, 챗봇은 인증 없이 접근 가능해야 한다.
- 언어와 필터는 비민감한 로컬 환경 설정으로 저장할 수 있다.
- 계정 종속 즐겨찾기나 `내 일정`을 임의로 만들지 않는다. 필요하다면 익명 로컬 저장과
  계정 기능 중 어느 것인지 먼저 결정한다.
- 관리자 도구는 공개 사용자 앱과 별도 보안 경계를 두고 서버에서 역할별 권한을
  검사한다. 관리자 작업은 감사 이력을 남기며 계정·권한 회수 절차를 갖춘다.
- 익명 챗봇과 공개 쓰기 요청에는 속도 제한, 남용 방지, 안전한 실패 응답을 적용한다.
- 개인정보와 비밀 값은 최소 수집·최소 권한·정해진 보관 기간 원칙을 적용하고 로그나
  클라이언트 번들에 노출하지 않는다.
- 입력 검증, 출력 이스케이프, 보안 헤더, CORS·CSRF, 파일 업로드, 의존성 취약점 대응을
  운영 환경의 위협 모델과 함께 관리한다.

## 8. 다국어 원칙과 결정 대기

- 번역 대상 후보: UI, 행사명, 공간·카테고리, 무대·공연, 아티스트·팀, 부스·운영자,
  메뉴, 공지, 링크 제목, 챗봇 답변. 실제 범위와 제공·승인 주체는 결정 대기
- API v1은 `ko`, `en`, `zh`와 언어 선택 계약을 제공한다.
- 요청 언어 번역이 없을 때의 fallback과 실제 응답 locale을 응답에 포함한다.
- 캐시 키와 검색 인덱스에 locale을 포함한다.
- `zh`가 간체인지 번체인지 결정해야 한다.
- 학교 건물·조직·프로그램은 기계 번역으로 공식 명칭을 만들지 않는다.
- 지도 이미지 안의 글자는 언어별 자산 또는 오버레이 텍스트로 분리한다.
- 누락 번역은 게시 검증에서 탐지하고, 허용된 fallback을 쓴 경우 사용자와 운영자가
  실제 응답 언어를 확인할 수 있게 한다.

## 9. 시간 규칙

- 기준 시간대는 API v1의 `Asia/Seoul`이며 응답에도 명시한다.
- 현재 공연 경계는 모든 화면과 API에서 동일한 규칙을 사용한다.
- 서버 시각과 timezone을 제공해 홈·시간표의 `현재` 계산이 어긋나지 않게 한다.
- 여러 무대의 동시 공연을 배열로 표현하고 홈 노출 우선순위를 별도 정책으로 둔다.
- 지연, 취소, 시간 변경, 갱신 시각, 정렬·겹침 검증과 캐시 무효화를 정의한다.
- 운영 변경은 하나의 revision으로 게시해 홈, 타임테이블, 상세가 서로 다른 일정을
  보여주지 않게 한다.

## 10. 지도 데이터 원칙

- 일러스트 지도를 채택한 경우 비율 좌표를 특정 `mapVersion`, 원본 크기, 실제
  콘텐츠 bounds, marker anchor에 묶는다. 일반 지도 좌표와 한 marker에서 섞지 않는다.
- 지도 자산 교체·crop·투명 여백 변경 시 새 버전과 검증된 좌표를 함께 게시한다.
- area와 category는 다른 축이며 필터 조합 규칙을 명시한다.
- `FestivalSpace`와 `MapMarker` 관계의 소유자와 cardinality를 하나로 정한다.
- 지도에는 목록 또는 텍스트 대체 경로를 제공한다.
- 지도 자산과 마커가 서로 다른 version인 상태는 공개하지 않는다. 게시 실패 시 직전의
  일관된 version을 유지한다.

## 11. 콘텐츠 운영과 게시

- 라인업, 공연, 공간, 지도, 공지, 외부 링크와 번역은 축제 회차에 귀속되는 운영
  콘텐츠로 관리한다.
- 콘텐츠는 최소 `draft / scheduled / published / archived` 상태, revision, 작성자,
  승인·게시·수정 시각과 감사 이력을 갖는다.
- 공개 서비스는 승인된 published revision만 읽는다. 운영자는 미리보기에서 locale,
  시간대, 링크, 이미지, 필수 텍스트, 지도 좌표와 관련 객체 정합성을 검증한다.
- 일정·지도처럼 서로 의존하는 변경은 부분 게시하지 않는다. 예약 게시의 시간대와
  실패 처리, 중복 실행 안전성을 명시한다.
- 긴급 공지는 일반 콘텐츠보다 우선해 즉시 게시·수정·회수할 수 있고, 게시 결과와 캐시
  반영 상태를 운영자가 확인할 수 있어야 한다.
- 잘못 게시한 콘텐츠를 직전의 검증된 revision으로 빠르게 되돌리는 rollback 기능과
  권한·절차를 둔다.

## 12. 캐시, 장애 대응과 복구

- 캐시 키에는 축제 회차, revision, locale, map version과 필터 등 응답을 바꾸는 값을
  포함한다.
- 긴급 공지와 현재 공연은 짧은 신선도 정책과 명시적 purge를 사용한다. 해시 또는 version이
  고정된 지도·이미지 자산은 장기 캐시한다.
- 관리자 게시·회수 성공은 관련 API, CDN, 클라이언트 캐시의 무효화 완료 여부까지
  추적한다.
- API 또는 네트워크 장애 시 직전의 검증된 데이터를 제한적으로 제공할 수 있으나 마지막
  갱신 시각과 stale 상태를 분명히 표시한다. 안전과 관련된 긴급 공지를 무기한 캐시하지 않는다.
- 데이터, 콘텐츠 revision, 지도 자산과 운영 설정을 정기 백업하고 복구 시점·복구 시간
  목표를 운영 전에 정한다. 복원 훈련과 행사 전 리허설로 실제 복구 가능성을 검증한다.
- 배포, 스키마 마이그레이션, 대량 게시마다 rollback 조건, 실행자, 사용자 안내와
  사후 검증 절차를 runbook에 둔다.

## 13. 접근성, 성능과 관측성

- 공개 사용자 화면은 WCAG 2.2 AA를 목표로 한다. 키보드, 스크린리더, 확대·reflow,
  포커스, 대비, 터치 영역, 동작 감소를 자동·수동으로 검증한다.
- 색상, 지도, 이미지 메뉴판만으로 정보를 전달하지 않고 동등한 구조화 텍스트 경로를
  제공한다.
- 실제 모바일 사용자의 75번째 백분위에서 `LCP ≤ 2.5s`, `INP ≤ 200ms`,
  `CLS ≤ 0.1`을 출시 성능 목표로 삼는다.
- 초기 화면은 현재 일정과 중요 공지를 우선 로드한다. 반응형 이미지, 압축, 지연 로딩,
  코드 분할과 요청 수 제한을 적용하고 저속 네트워크와 피크 트래픽을 시험한다.
- 구조화 로그, 요청 추적, 서버·클라이언트 지표를 통해 오류율·지연, 캐시 hit와 stale,
  게시 실패, 챗봇 실패, 핵심 사용자 흐름을 관찰한다. 관측 데이터에는 개인정보를 넣지 않는다.
- 서비스 수준 목표, 경보 임계치, 온콜 담당자와 장애 runbook을 운영 전에 확정한다.
  health check와 smoke test 실패는 자동 또는 승인된 rollback으로 연결한다.

## 14. API v1 계약과 현재 검증 구조

API v1은 공개 앱과 관리자 운영 도구가 공유하는 HTTP 계약이다. 구현 기술 스택과
독립적으로 URI, 요청·응답, 인증 경계, 오류, pagination, locale, 시간대,
캐시·동시성 규칙을 정의한다. 최초 서비스 scaffold는 같은 계약의 OpenAPI artifact와
계약 테스트를 추가한다.

공개 API의 핵심 기능은 다음과 같다.

- 홈 집계
- 아티스트 목록
- 공연 목록·상세
- 축제 공간 목록·상세
- 지도 메타데이터와 마커 목록·상세
- 공지 목록·상세
- 챗봇 메시지

아티스트 검색·상세·SNS·추천곡과 FAQ·공식 외부 링크는 API schema의 capability로만
준비하며, 제품 승인과 회차별 활성화 전에는 공개 기능으로 취급하지 않는다.

계약 원칙:

- 공개 조회와 챗봇 진입은 사용자 인증을 요구하지 않는다. 관리자 API는 별도 인증·권한
  경계를 사용한다.
- 공통 응답과 오류 형식, 안정적 pagination과 정렬, request ID를 일관되게 적용한다.
- locale fallback과 실제 응답 locale, 축제 회차, 콘텐츠 revision, map version,
  서버 시각과 timezone을 필요한 응답에 포함한다.
- 여러 무대의 동시 공연, 공연 상태, 콘텐츠 게시 상태, 구조화 메뉴, 의무실과 공연장
  전체를 표현할 수 있어야 한다.
- v1 필드 제거, 의미 변경, enum 재해석처럼 기존 클라이언트를 깨는 변경은 새 버전과
  마이그레이션 계획 없이 배포하지 않는다.
- 계약 변경은 OpenAPI 또는 동등한 명세, 예시, consumer·provider 계약 테스트를 같은
  변경에서 갱신한다.

`test/frontend`의 Next.js UI, `test/backend`의 Spring Boot API,
`test/docker-compose.yml`과 Caddy 구성은 PWA·스탬프·Web Push의 실기기 검증
환경이다. 실행·보안·복구 기준은 `test/README.md`와
`test/docs/FREE_SERVER_DEPLOYMENT.md`에 기록한다. 이 검증 환경은 해당 기능의 공개
서비스 채택이나 전체 제품 아키텍처를 대신 결정하지 않는다.

## 15. 확정된 용어 결정

- `호공`, `학정`, `4공`, `체대`의 풀네임은 각각 `호수공원`, `학술정보관`,
  `제4공학관`, `예체능대학`이다.
- 공식 표기는 `민주광장`이다.
- 호수공원 이벤트존과 호수공원 앞 피크닉존은 별도 구역이다.
- 매표소, 티켓부스, 티켓 수령 부스는 같은 물리적 장소다.
- 의무실은 지도 카테고리에 포함한다.
- 공연장은 게이트를 포함한 공연장 전체를 뜻한다.
