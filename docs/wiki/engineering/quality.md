# 접근성·성능·관측성

[위키 홈](../README.md) · 읽는 때: UI·성능·로그·지표·출시 검증 변경

- 공개 사용자 화면은 WCAG 2.2 AA를 목표로 한다. 키보드, 스크린리더, 확대·reflow,
  포커스, 대비, 터치 영역, 동작 감소를 자동·수동으로 검증한다.
- 색상, 지도, 이미지 메뉴판만으로 정보를 전달하지 않고 동등한 구조화 텍스트 경로를
  제공한다.
- 실제 모바일 사용자의 75번째 백분위에서 `LCP ≤ 2.5s`, `INP ≤ 200ms`,
  `CLS ≤ 0.1`을 출시 성능 목표로 삼는다.
- 초기 화면은 현재 일정과 중요 공지를 우선 로드한다. 반응형 이미지, 압축, 지연 로딩,
  코드 분할과 요청 수 제한을 적용하고 저속 네트워크와 피크 트래픽을 시험한다.
- 구조화 로그, 요청 추적, 서버·클라이언트 지표를 통해 오류율·지연, 캐시 hit와 stale,
  게시 실패, 챗봇 실패, 핵심 사용자 흐름을 관찰한다. 관측 데이터에는 개인정보를 넣지 않는다.
- 서비스 수준 목표, 경보 임계치, 온콜 담당자와 장애 runbook을 운영 전에 확정한다.
  health check와 smoke test 실패는 자동 또는 승인된 rollback으로 연결한다.

## 구현 규칙

- 공개 사용자 화면은 WCAG 2.2 AA를 목표로 구현하고 자동 검사와 키보드·스크린리더
  수동 검증을 함께 수행한다.
- 의미 구조, 포커스 순서와 표시, 충분한 대비, 44×44 CSS px 수준의 터치 영역,
  확대·reflow, 동작 감소 설정을 지원한다. 색상·지도·이미지만으로 정보를 전달하지 않는다.
- 실제 모바일 환경의 75번째 백분위에서 Core Web Vitals 권장 기준인
  `LCP ≤ 2.5s`, `INP ≤ 200ms`, `CLS ≤ 0.1`을 출시 성능 목표로 삼는다.
- 초기 화면의 필수 정보와 긴급 공지를 우선 전송하고 이미지 크기·형식·해상도를 최적화한다.
  저속 네트워크와 행사 피크 트래픽을 포함한 부하·복원력 테스트를 출시 전에 수행한다.
- 구조화 로그, 지표, 분산 추적 또는 동등한 요청 추적을 갖추고 API 오류율·지연,
  캐시 상태, 게시 실패, 챗봇 실패, 클라이언트 오류를 대시보드와 경보로 연결한다.
- 서비스 수준 목표, 경보 임계치, 온콜 연락망, 장애 대응·복구 runbook을 운영 전에
  확정한다. 관측 데이터는 locale·기능·revision별 문제를 찾을 수 있어야 하며 개인정보는
  포함하지 않는다.
- staging에서 운영과 동일한 배포·마이그레이션·캐시 무효화 경로를 검증한다. 배포 후
  health check와 핵심 사용자 흐름의 smoke test가 실패하면 롤백한다.
