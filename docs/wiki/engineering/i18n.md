# 다국어

[위키 홈](../README.md) · 읽는 때: 사용자 문자열·콘텐츠·검색·locale·번역 변경

- 번역 대상 후보: UI, 행사명, 공간·카테고리, 무대·공연, 아티스트·팀, 부스·운영자,
  메뉴, 공지, 링크 제목, 챗봇 답변. 실제 범위와 제공·승인 주체는 결정 대기
- API v1은 `ko`, `en`, `zh`와 언어 선택 계약을 제공한다.
- 요청 언어 번역이 없을 때의 fallback과 실제 응답 locale을 응답에 포함한다.
- 캐시 키와 검색 인덱스에 locale을 포함한다.
- `zh`가 간체인지 번체인지 결정해야 한다.
- 학교 건물·조직·프로그램은 기계 번역으로 공식 명칭을 만들지 않는다.
- 지도 이미지 안의 글자는 언어별 자산 또는 오버레이 텍스트로 분리한다.
- 누락 번역은 게시 검증에서 탐지하고, 허용된 fallback을 쓴 경우 사용자와 운영자가
  실제 응답 언어를 확인할 수 있게 한다.

## 구현 규칙

- 사용자 노출 문자열을 컴포넌트에 직접 하드코딩하지 않는다.
- UI뿐 아니라 축제명, 공간·카테고리, 무대·공연, 아티스트, 부스·메뉴, 공지,
  외부 링크 제목, 챗봇 답변을 locale별 운영 콘텐츠로 다룬다. 실제 번역 제공 범위와
  승인 주체는 제품 결정으로 확정한다.
- API v1의 locale은 `ko`, `en`, `zh`이고 `ja`는 후순위다. `zh`의 간체·번체
  선택과 한국어 기본값은 최종 결정 전 구성 가능하게 유지한다.
- 누락 번역 fallback과 실제 응답 locale을 API 계약에 명시하며, 사용자가 보고 있는
  언어와 응답 언어가 다르면 접근 가능한 방식으로 알린다.
- 단일 언어 문자가 포함된 래스터 지도만으로 다국어 지원을 충족했다고 보지 않는다.
  언어별 자산, 오버레이 텍스트, 접근 가능한 텍스트 대체 중 적합한 방식을 결정한다.
- 이미지 메뉴판만으로 끝내지 않고 검색·스크린리더·번역에 사용할 구조화 텍스트를
  제공한다.
