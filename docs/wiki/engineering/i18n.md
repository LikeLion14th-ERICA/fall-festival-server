# 다국어

[위키 홈](../README.md) · 읽는 때: 사용자 문자열·콘텐츠·검색·locale·번역 변경

## 제품 기준

[HOME-002](../product/home.md)의 언어 선택 동작과
[NOTICE-001](../product/notice.md)의 공지 노출 규칙을 우선한다.

- 저장된 선택값이 없으면 브라우저 언어와 관계없이 한국어를 표시한다. 한국어 기본값은 확정이다.
- 한국어를 기본 제공하고 영어, 중국어 간체, 일본어 순으로 준비한다. 중국어는 간체로 확정이다.
- 번역·전환 구현·언어별 디자인 점검이 완료된 언어만 원어 이름으로 선택 목록에 표시한다.
- 선택 즉시 적용하고 성공 후에만 같은 기기·브라우저에 저장한다. 페이지·스크롤·날짜·필터는 유지한다.
- 전환 실패 시 이전 언어와 저장값을 유지하며 이전 언어로 하단 오류 안내를 3초 표시한다.
- 이미지에 포함된 글자를 제외한 앱 내부 전체 텍스트에 선택 언어를 적용한다.
  지도 등 이미지 안의 글자는 원본 유지·번역 제외이며 언어별 이미지 제작을 필수로 요구하지 않는다.
- FAQ와 외부 공지 페이지는 앱 번역 범위에서 제외한다. FAQ는 외부 페이지 링크로만
  제공하며 해당 페이지의 언어 정책은 외부 페이지 담당자가 정한다.
- 학교 건물·조직·프로그램의 공식 번역은 [학교 용어](../product/terminology.md)를 따른다.
  기계 번역으로 공식 명칭을 만들지 않는다.

## 공지 번역과 노출

- 예상 가능한 공지는 언어별로 사전 준비한다. 새 한국어 공지는 제공 중인 언어로 자동
  번역하며 모든 공지의 영어 번역을 반드시 준비한다.
- 사용자에게는 선택 언어의 번역이 완료된 공지만 노출한다. 번역이 없으면 해당 언어에서
  제외하고 다른 언어로 대체하거나 `번역 준비 중` 안내를 표시하지 않는다.
- 이 규칙은 홈 최신 공지와 알림 메시지 목록에 함께 적용한다.
- 누락 번역은 언어별 게시 검증에서 탐지한다. 외국어 미완료·실패는 한국어 게시를
  막지 않는다. 번역 누락을 일반 fallback으로 숨기지 않는다.

## 구현 규칙

- 사용자 노출 문자열을 컴포넌트에 직접 하드코딩하지 않는다.
- UI, 축제명, 공간·카테고리, 무대·공연, 아티스트·팀, 부스·메뉴·공지와 링크 제목 등
  현재 제품 범위의 앱 내부 텍스트를 locale별로 준비한다. 이 지침으로 미정 기능을 추가하지 않는다.
- 캐시 키와 검색 인덱스에 locale을 포함한다. 검색이 없는 기능에 검색을 추가하는 요구는 아니다.
- 주점 메뉴명·가격은 [BOOTH-001](../product/spaces.md)에 따라 텍스트로 제공한다.
  이미지 번역 제외와 접근성을 위한 텍스트 제공은 구분한다.

## 기존 API 계약과 동기화

API v1은 기존 `ko`, `en`, `zh` 계약을 갖는다. 이는 최신 제품의 한국어 기본값·중국어
간체·일본어 준비 순위·공지 번역 미완료 시 미노출 규칙을 무효로 하지 않는다.

구현 전 locale 지원과 기본값, 실제 응답 언어, 번역 누락 처리 및 공지 필터를 최신
제품 기준에 맞춰 API 계약·영향받는 코드·테스트와 함께 동기화한다. 공지 외 콘텐츠의
fallback은 제품 규칙을 어기지 않는 범위에서 별도로 정의하며 임의 허용하지 않는다.
이번 제품 문서 보완은 API 원문이나 코드 변경을 포함하지 않는다.

## 관리자 공지 템플릿

[ADM-NOTICE-004](../product/admin/notice.md)의 원문과 준비된 번역을 불러온다.
영어는 모든 공지의 준비 대상이나 영어 완료를 한국어 저장 조건으로 삼지 않는다.
번역이 없거나 실패해도 직접 작성과 한국어 우선 게시를 허용한다. 게시 전 템플릿
원문을 바꾸면 기존 번역을 그대로 게시하지 않고 변경된 원문에 맞춰 준비한다.
사용자 노출은 선택 언어의 READY 항목만 허용하며 원본 템플릿은 수정하지 않는다.
