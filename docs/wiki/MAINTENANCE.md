# 위키 관리 규칙

[위키 홈](README.md) · 읽는 때: 컨텍스트·규칙 문서 변경

## 파일 역할

- 루트 AGENTS.md: 항상 적용할 짧은 규칙과 읽기 절차. 상세 규칙은 넣지 않는다.
- START_HERE.md: 최초 숙지 경로. 전체 파일 일괄 읽기를 요구하지 않는다.
- README.md: 작업별 필수 페이지와 조건부 자료를 연결한다.
- product/: 제품 범위·화면 의도·용어·결정 상태.
- engineering/: 보안·다국어·API·게시·운영·품질 규칙.
- workflow/: 작업 격리·브랜치·커밋·PR·검증·릴리스 규칙.
- PRODUCT_CONTEXT.md와 CONTRIBUTING.md: 기존 링크를 보존하는 목차.

## 변경 절차

1. 담당 주제 페이지에서 규칙을 수정한다. 상세 내용을 루트·목차에 복사하지 않는다.
2. 새 주제는 읽는 시점과 위키 홈 링크를 포함한 페이지로 만들고 작업별 읽기 표와
   관련 목차에 연결한다. 하나의 작업 주제로 묶고 150줄 안팎을 넘으면 분할을 검토한다.
3. 이동 시 원문의 모든 요구를 대조한다. 중복을 줄이더라도 예외·승인·보안·검증 조건을
   누락하지 않는다. 다른 도메인에도 영향을 주면 요약 대신 담당 페이지 링크를 연결한다.
4. API 계약·실행 명령·배포 절차는 원문과 동일 변경에서 맞춘다. 예시와 실제 검증,
   기술 설계 채택과 운영 공개 승인을 구분한다.
5. 상대 링크·앵커·기존 경로·PR 템플릿·작업별 읽기 표를 검사한다.
6. `git diff --check`와 문서 링크 검사를 실행한다. 문서만 바뀌었다면 앱 테스트를
   실행하지 않은 사유를 기록한다. 실행·API 계약도 바뀌었다면 해당 검증을 수행한다.

## 변경에 따른 다시 읽기

같은 작업에서 이미 읽은 페이지는 내용이 그대로라면 재사용할 수 있다.
새 작업 범위, 문서 변경 또는 컨텍스트 유실 시 해당 페이지를 다시 읽는다.
중요한 규칙을 링크 깊숙이 숨겨 선택 과정에서 빠지게 하지 않는다.
