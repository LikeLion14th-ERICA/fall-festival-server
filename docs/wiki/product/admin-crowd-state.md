# 관리자 혼잡도 데이터·반영·검증

[위키 홈](../README.md) · [관리자 기능 목차](admin.md) · 읽는 때: 혼잡도 데이터·동시 수정·오류·완료 기준 변경

## 6. 상태 데이터 구분

관리자가 저장하는 혼잡도와 사용자에게 최종적으로 표시되는 상태를 구분한다.

### 관리자 저장 가능 혼잡도

- 보통
- 여유
- 혼잡
- 만석

### 시스템 최종 노출 가능 상태

- 운영 전
- 여유
- 보통
- 혼잡
- 만석
- 운영 종료

`운영 전`과 `운영 종료`는 별도의 혼잡도 데이터로 저장하지 않으며 현재 시각과 운영 시간 정보를 기준으로 시스템이 자동 결정한다.

## 7. 최종 수정 시각 규칙

| 항목 | 규칙 |
| --- | --- |
| 수정 시각 생성 기준 | 서버에서 혼잡도 변경 저장이 성공한 시각 |
| 시간 기준 | KST(Asia/Seoul) 기준 |
| 수정 시각 갱신 | 새로운 혼잡도 상태 저장에 성공한 경우에만 갱신 |
| 저장 실패 | 기존 최종 수정 시각 유지 |
| 동일 상태 선택 | 수정 시각 갱신하지 않음 |
| 최초 상태 | 운영자가 당일 한 번도 상태를 변경하지 않은 경우 실제 수정 시각 대신 `운영 시작 기준`을 표시 |
| 운영 시간 연장 후 재개 | 기존 당일 최종 수정 시각 유지 |

`운영 시작 기준`은 실제 수정 시간을 의미하지 않으며, 해당 운영일에 운영자가 아직 혼잡도를 직접 변경하지 않았음을 의미한다.

## 8. 사용자 화면 반영 규칙

| 항목 | 규칙 |
| --- | --- |
| 반영 대상 | 상태명, 상태 색상, 사용자 안내 문구, 마지막 업데이트 시각 또는 `운영 시작 기준` |
| 반영 화면 | 사용자 웹 홈 / 지도 |
| 데이터 기준 | 홈과 지도에서 동일한 혼잡도 데이터를 사용한다. |
| 반영 조건 | 관리자 상태 저장 성공 이후 |
| 반영 방식 | 사용자가 직접 새로고침하지 않아도 최신 상태가 반영되어야 한다. |
| 반영 시간 | 관리자 저장 성공 후 최대 5초 이내 사용자 홈과 지도에 최신 상태가 반영되어야 한다. |
| 구현 방식 | 실시간 반영 방식은 WebSocket, SSE, Polling 등 개발 환경에 맞춰 개발팀에서 결정한다. |
| 지도 표시 | 혼잡도 상태별 지정 색상을 사용하며 `만석`은 검정색으로 표시한다. |
| 수정 시각 | 관리자 상태 변경 저장 성공 시 갱신된 시각을 사용자 화면에 반영한다. |
| 최초 상태 | 운영자가 해당 운영일에 아직 상태를 변경하지 않았다면 `운영 시작 기준`을 표시한다. |
| 운영 전 | 혼잡도 대신 `운영 전` 상태를 표시한다. |
| 운영 종료 | 혼잡도 대신 `운영 종료` 상태를 표시한다. |

## 9. 복수 관리자 동시 수정 처리

| 상황 | 처리 |
| --- | --- |
| 복수 관리자가 동시에 상태 변경 | 서버에 마지막으로 저장 성공한 상태를 최종 혼잡도로 적용한다. |
| 이전 요청이 먼저 성공 | 이후 저장에 성공한 요청이 최종 상태를 덮어쓴다. |
| 관리자 화면 | 최종 저장 상태를 기준으로 최신 혼잡도 및 수정 시각을 표시한다. |
| 사용자 화면 | 서버에 마지막으로 저장 성공한 최신 상태를 표시한다. |
| 데이터 기준 | 각 관리자 클라이언트에서 선택한 값이 아니라 서버의 최종 저장값을 기준으로 한다. |

## 10. 예외 상황 및 오류 처리

| 상황 | 대응 |
| --- | --- |
| 혼잡도 저장 실패 | 변경 사항을 적용하지 않고 기존 혼잡도를 유지한다. |
| 저장 실패 후 관리자 화면 | 선택된 상태 UI를 기존 정상 저장 상태로 복원한다. |
| 저장 실패 시각 | 기존 최종 수정 시각을 유지한다. |
| 저장 실패 오류 메시지 | `변경사항을 저장하지 못했습니다. 다시 시도해주세요.` |
| 저장 처리 중 추가 선택 | 기존 저장 요청이 완료되기 전까지 추가 상태 변경 요청을 제한한다. |
| 사용자 화면 자동 갱신 실패 | 마지막으로 정상 수신한 혼잡도와 수정 시각을 유지한다. |
| 자동 갱신 재성공 | 서버의 최신 혼잡도와 수정 시각으로 갱신한다. |
| 복수 관리자 동시 변경 | 마지막으로 서버 저장에 성공한 상태를 최종 상태로 적용한다. |
| 운영 시간 정보 조회 실패 | 운영 시간 관련 공통 오류 정책을 적용하며 임의의 운영 상태를 생성하지 않는다. |
| 운영 시간 미설정 | 별도 운영 시간 관리 기능의 미설정 정책을 따른다. |

## 11. 동작 규칙

| 항목 | 규칙 |
| --- | --- |
| 혼잡도 변경 권한 | 관리자 페이지 접근 권한을 가진 운영자만 변경 가능 |
| 선택 가능 상태 | `여유 / 보통 / 혼잡 / 만석` |
| 자동 적용 상태 | `운영 전 / 운영 종료` |
| 상태 변경 방식 | 버튼 선택 방식 |
| 별도 저장 버튼 | 사용하지 않음 |
| 만석 변경 | 확인창 확인 필수 |
| 상태 독립성 | 현재 상태에 관계없이 다른 혼잡도 상태로 변경 가능 |
| 동일 상태 재선택 | 저장 요청 없음 |
| 수정 시각 | 서버 저장 성공 시각 기준 |
| 사용자 반영 | 저장 성공 후 최대 5초 이내 |
| 데이터 기준 | 서버의 최신 저장값 |
| 홈·지도 데이터 | 동일 데이터 사용 |
| 운영일 초기화 | 새로운 운영일에 직전 운영일 혼잡도 미이월 |

## 12. 완료 기준

| 확인 항목 | 완료 기준 |
| --- | --- |
| 현재 상태 조회 | 관리자가 현재 적용 중인 혼잡도와 최종 수정 시각을 확인할 수 있다. |
| 상태 변경 | 관리자가 `여유 / 보통 / 혼잡 / 만석`으로 변경할 수 있다. |
| 즉시 저장 | 여유·보통·혼잡 선택 시 별도 저장 버튼 없이 저장 요청이 진행된다. |
| 만석 처리 | 만석 선택 시 확인창을 거친 후 변경할 수 있다. |
| 동일 상태 처리 | 현재 상태를 다시 선택해도 저장 요청 및 수정 시각 변경이 발생하지 않는다. |
| 자동 반영 | 관리자 저장 성공 후 최대 5초 이내 홈과 지도에 동일한 상태가 반영된다. |
| 수정 시각 | 상태 저장 성공 시 서버 저장 시각 기준으로 최종 수정 시각이 갱신된다. |
| 최초 상태 | 운영자 수정 전 `여유` 및 `운영 시작 기준`이 적용된다. |
| 운영 전 | 운영 시작 시각 이전에는 사용자 화면에 `운영 전`이 표시된다. |
| 운영 종료 | 운영 종료 시각 이후에는 사용자 화면에 `운영 종료`가 표시된다. |
| 운영 시간 연장 | 운영 시간이 연장되어 운영 시간 내로 다시 진입하면 당일 마지막 혼잡도와 수정 시각이 복원된다. |
| 운영일 초기화 | 새로운 운영일에는 직전 운영일 혼잡도를 이월하지 않는다. |
| 복수 관리자 수정 | 서버에서 마지막으로 저장 성공한 상태가 최종 상태로 적용된다. |
| 저장 중 중복 입력 | 저장 요청 중 추가 상태 변경 요청이 중복 발생하지 않는다. |
| 저장 실패 | 기존 상태와 수정 시각을 유지하고 오류 메시지를 표시한다. |
| 자동 갱신 실패 | 마지막 정상 상태를 유지하며 이후 정상 통신 시 최신 상태로 갱신한다. |
| 홈·지도 정합성 | 홈과 지도에서 동일한 혼잡도 상태, 색상, 안내 문구 및 업데이트 정보를 표시한다. |

상태 선택과 운영 시간 처리는 [혼잡도 관리](admin-crowd.md)를 함께 따른다.
