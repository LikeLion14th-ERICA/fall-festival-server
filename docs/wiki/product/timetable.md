# 타임테이블

[위키 홈](../README.md) · 읽는 때: 해당 화면·데이터·API 변경

- 현재 시각선 표시와 현재 공연 강조
- Figma 의도: 메인 스테이지, DAY 1/2/3 컬럼, 17:00–22:00, 30분 눈금
- FigJam에는 날짜별·무대별 일정과 공연 상세 Bottom Sheet가 함께 표현돼 있다.
- 실제 행사 일수, 무대 수, 공연 상세 동작, 동시 공연 표시 규칙은 운영 자료로 확정한다.
- 지연·취소·시간 변경과 마지막 갱신 시각을 사용자가 구분할 수 있어야 한다.

## 시간 계약

- 기준 시간대는 API v1의 `Asia/Seoul`이며 응답에도 명시한다.
- 현재 공연 경계는 모든 화면과 API에서 동일한 규칙을 사용한다.
- 서버 시각과 timezone을 제공해 홈·시간표의 `현재` 계산이 어긋나지 않게 한다.
- 여러 무대의 동시 공연을 배열로 표현하고 홈 노출 우선순위를 별도 정책으로 둔다.
- 지연, 취소, 시간 변경, 갱신 시각, 정렬·겹침 검증과 캐시 무효화를 정의한다.
- 운영 변경은 하나의 revision으로 게시해 홈, 타임테이블, 상세가 서로 다른 일정을
  보여주지 않게 한다.

## 구현 규칙

- 축제 기준 시간대는 API v1의 `Asia/Seoul`이며 기기의 현지 시간대만으로 현재
  공연을 계산하지 않는다.
- 현재 공연 경계 규칙, 서버 시각, 시작·종료 시각 표현, 캐시 갱신을 하나의 계약으로
  정의한다.
- 홈과 타임테이블은 같은 공연 데이터와 같은 `now` 규칙을 사용해야 한다.
- 여러 무대의 동시 공연을 지원하고, 지연·취소·시간 변경 상태와 노출 우선순위를
  데이터로 표현한다.
- 일정 변경이 게시되면 홈, 시간표, 상세, 검색, 캐시가 동일한 revision으로 전환되어야
  하며 사용자에게 마지막 갱신 시각과 변경 상태를 제공한다.
