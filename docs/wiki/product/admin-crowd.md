| 기본 표시 정보 | 현재 혼잡도, 상태 선택 버튼, 사용자 노출 문구, 최종 수정 시각 |

## 1. 혼잡도 단계 및 판단 방식

| 상태 | 운영자 판단 기준 | 색상 | 사용자 노출 문구 |
| --- | --- | --- | --- |
| 여유 | 공간 점유율 추정치 50% 이하 | 초록 | 재학생존의 공간이 많이 남았어요. |
| 보통 | 공간 점유율 추정치 50% 초과 ~ 70% 이하 | 주황 | 재학생존의 공간이 절반 이상 찼어요. |
| 혼잡 | 공간 점유율 추정치 70% 초과 ~ 입장 통제 전 | 빨강 | 재학생존이 많이 혼잡해요. |
| 만석 | 재학생존 추가 입장 통제 시작 | 검정 | 재학생존이 꽉 차서 외부인존에서만 즐길 수 있어요. |

### 혼잡도 판단 규칙

| 항목 | 규칙 |
| --- | --- |
| 판단 방식 | 실제 인원 수를 집계하지 않고 현장 운영자의 관찰을 통해 혼잡도를 판단한다. |
| 퍼센트 기준 | 공간 점유율 퍼센트는 운영자의 판단을 돕기 위한 내부 참고 기준으로만 사용한다. |
| 사용자 노출 | 사용자 화면에는 공간 점유율 퍼센트를 표시하지 않는다. |
| 만석 의미 | 재학생존의 추가 입장을 제한 또는 통제하고 있는 상태를 의미한다. |
| 관리자 선택 가능 상태 | 관리자가 직접 선택할 수 있는 상태는 `여유 / 보통 / 혼잡 / 만석` 4가지이다. |
| 시스템 자동 상태 | `운영 전 / 운영 종료`는 운영 시간에 따라 시스템이 자동 적용하며 관리자가 직접 선택하지 않는다. |
| 색상 코드 | 상세 색상 값은 디자인팀에서 별도로 정의한다. |

## 2. 사용자 행동과 처리 흐름

| 순서 | 관리자 동작 및 시스템 처리 |
| --- | --- |
| 1 | 관리자가 대운동장 혼잡도 관리 화면에 진입한다. |
| 2 | 시스템이 현재 적용 중인 혼잡도와 최종 수정 시각을 표시한다. |
| 3 | 관리자가 `여유 / 보통 / 혼잡 / 만석` 중 변경할 상태를 선택한다. |
| 4 | `여유 / 보통 / 혼잡` 선택 시 별도 확인 과정 없이 즉시 저장 요청을 진행한다. |
| 5 | `만석` 선택 시 확인창을 표시한다. |
| 6 | 관리자가 확인창에서 `만석으로 변경`을 선택하면 저장 요청을 진행한다. |
| 7 | 저장 성공 시 선택한 혼잡도를 적용하고 최종 수정 시각을 갱신한다. |
| 8 | 변경된 상태를 사용자 웹의 홈과 지도에 동일하게 반영한다. |
| 9 | 관리자 화면에도 서버에 최종 저장된 혼잡도와 수정 시각을 표시한다. |

## 3. 상태 변경 규칙

| 항목 | 규칙 |
| --- | --- |
| 저장 방식 | 별도의 저장 버튼을 사용하지 않는다. 상태 선택 자체를 저장 동작으로 처리한다. |
| 여유·보통·혼잡 | 상태 선택 즉시 저장 요청을 진행한다. |
| 만석 | 확인창에서 최종 확인 후 저장 요청을 진행한다. |
| 동일 상태 재선택 | 현재 적용 중인 상태와 동일한 상태를 선택한 경우 저장 요청을 발생시키지 않는다. |
| 동일 상태 수정 시각 | 동일 상태를 다시 선택해도 최종 수정 시각은 갱신하지 않는다. |
| 저장 중 중복 입력 | 저장 요청 처리 중에는 추가 상태 변경 요청이 발생하지 않도록 상태 버튼 입력을 제한한다. |
| 저장 성공 기준 | 서버에서 혼잡도 변경 요청이 정상적으로 저장된 경우에만 변경 완료로 처리한다. |
| 최종 상태 기준 | 관리자 화면에서 선택한 값이 아니라 서버에 최종 저장된 값을 실제 적용 상태로 사용한다. |

## 4. 만석 확인창

| 항목 | 내용 |
| --- | --- |
| 노출 조건 | 관리자가 `만석` 상태를 선택한 경우 |
| 안내 문구 | `재학생존을 만석으로 변경하시겠습니까?` |
| 확인 버튼 | `만석으로 변경` |
| 확인 동작 | 만석 상태 저장 요청 진행 |
| 취소 버튼 | `취소` |
| 취소 동작 | 확인창을 닫고 기존 혼잡도 상태 유지 |
| 저장 실패 | 기존 상태를 유지하고 오류 메시지 표시 |

## 5. 운영 시간 및 초기 상태 연동

혼잡도 관리 기능은 별도 운영 시간 관리 기능에 등록된 대운동장 운영 시작 및 종료 시각을 기준으로 동작한다.

| 상황 | 처리 |
| --- | --- |
| 당일 운영 시작 전 | 혼잡도 대신 `운영 전` 상태를 사용자 화면에 표시한다. |
| 운영 시작 시 당일 수정 이력 없음 | 기본 혼잡도 `여유`를 적용한다. |
| 운영 시작 후 수정 이력 없음 | 사용자 화면의 수정 시각 영역에 `운영 시작 기준`을 표시한다. |
| 운영자 상태 변경 이후 | 운영자가 선택하고 저장한 혼잡도 및 최종 수정 시각을 적용한다. |
| 운영 종료 시각 이후 | 혼잡도 대신 `운영 종료` 상태를 사용자 화면에 표시한다. |
| 운영 종료 후 혼잡도 데이터 | 당일 마지막으로 저장한 혼잡도와 수정 시각은 시스템 내부에 유지한다. |
| 운영 시간 연장 후 운영 재개 | 당일 마지막으로 저장된 혼잡도와 최종 수정 시각을 다시 적용한다. |
| 재개 시 당일 수정 이력 없음 | `여유` 및 `운영 시작 기준`을 적용한다. |
| 새로운 운영일 시작 | 직전 운영일의 혼잡도 상태를 새로운 운영일에 이월하지 않는다. |
| 새로운 운영일 초기 상태 | 운영 시작 전에는 `운영 전`, 운영 시작 후 수정 이력이 없으면 `여유`를 적용한다. |

### 운영 시간 변경 규칙

| 항목 | 규칙 |
| --- | --- |
| 운영 시간 기준 | 별도 운영 시간 관리 기능에 저장된 값을 사용한다. |
| 운영 시간 수정 | 운영 시간이 변경되면 시스템은 현재 시각과 변경된 운영 시간을 다시 비교한다. |
| 운영 시작 전으로 변경 | 현재 시간이 변경된 시작 시각보다 이전이라면 `운영 전` 상태를 적용한다. |
| 운영 종료 후로 변경 | 현재 시간이 변경된 종료 시각 이후라면 `운영 종료` 상태를 적용한다. |
| 운영 시간 내로 재진입 | 현재 시간이 다시 운영 시간 범위에 포함되면 당일 마지막 저장 혼잡도를 복원한다. |
| 운영일 기준 | 단순한 날짜 변경 시각인 00:00이 아니라 해당 행사의 운영일 기준으로 혼잡도 데이터를 구분한다. |

상태 데이터·수정 시각·홈과 지도 반영·동시 수정·오류·완료 기준은
[혼잡도 데이터·반영·검증](admin-crowd-state.md)을 함께 따른다.
