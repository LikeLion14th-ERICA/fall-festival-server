# 관리자 재학생존 혼잡도

[위키 홈](../../README.md) · 읽는 때: 관리자 혼잡도·운영 시간 조회·변경과 사용자 홈 반영

## ADM-CROWD-001 · 재학생존 혼잡도 조회 및 변경

총학생회 현장 운영자가 재학생존 상태를 직접 판단해 변경하고 [HOME-001](../home.md)에
반영한다. 혼잡도는 사용자 홈에만 표시하며 지도에는 표시하지 않는다.

### 표시와 입력

- 현재 published FestivalDay 또는 관리자가 저장한 날짜별 일정에 따른
  `운영 전 / 운영 중 / 운영 종료`를 표시한다.
- 현재 저장된 `여유 / 보통 / 혼잡 / 만석` 상태와 최종 수정 시각을 표시한다.
- 각 상태의 사용자 안내 문구를 관리 화면에서 확인할 수 있다.
- 현장 상황을 본 담당자가 네 단계 중 하나를 직접 선택한다.
- 실제 인원·점유율 입력, 수치 계산과 자동 단계 판정은 제공하지 않는다.

| 상태 | 색상 | 현장 판단 참고 | 사용자 안내 |
|---|---|---|---|
| 여유 | 초록 | 점유율 약 50% 수준 | 재학생존의 공간이 많이 남았어요. |
| 보통 | 주황 | 점유율 약 70% 수준 | 재학생존의 공간이 절반 이상 찼어요. |
| 혼잡 | 빨강 | 점유율 약 85% 수준 | 재학생존이 많이 혼잡해요. |
| 만석 | 검정 | 실제 추가 입장 통제 시작 | 재학생존이 꽉 차서 외부인존에서만 즐길 수 있어요. |

퍼센트는 운영자 판단을 돕는 대략적인 참고값이며 시스템 계산이나 사용자 표시에는
사용하지 않는다. 색상 코드는 디자인팀이 확정한다.

### 변경 흐름

1. 현재 운영 상태·혼잡도·최종 수정 시각을 확인한다.
2. `여유 / 보통 / 혼잡` 선택은 별도 확인창 없이 저장을 요청한다.
3. `만석` 선택 시 `재학생존을 만석으로 변경하시겠습니까?` 확인창을 표시한다.
4. 확인하면 저장하고 취소하면 기존 상태를 유지한다.
5. 저장 성공 시 새 상태와 실제 저장 성공 시각을 관리자 화면과 사용자 홈에 반영한다.

같은 상태를 다시 선택하면 성공으로 처리하되 저장 행과 수정 시각은 바꾸지 않는다.
관리자·사용자 화면은 이전의 실제 저장 시각을 유지한다.

### 시간과 초기화

- 현재 `published FestivalRevision`의 `FestivalDay`가 공개 대상 축제일과 카탈로그 초기
  운영 시간을 제공한다. 날짜별 관리자 저장값이 있으면 그 값을 우선하고, 저장값이 없으면
  해당 게시본의 `opensAt`·`closesAt`을 사용한다.
- 공개 혼잡도 API가 사용할 게시 일정이 없거나, 게시된 축제일 중 관리자 저장값 또는 카탈로그
  초기값을 적용한 유효 시간이 없는 날이 있으면 `503 CROWDING_SCHEDULE_UNCONFIGURED`를
  반환한다. 관리자 조회는 잘못된 카탈로그 초기값도 원본 그대로 보여 주므로 유효한 시간으로
  저장해 복구할 수 있다.
- 운영 시간은 혼잡도 상태와 독립적으로 `(festival_id, operating_date)`에 저장한다.
  재게시·게시본 rollback·서버 재시작으로 초기화되지 않는다. 게시에서 제외된 날짜의
  저장값은 보존되지만 조회와 공개 시간 판정에서는 제외한다. 같은 날짜를 다시 게시하면
  기존 저장값을 다시 적용한다.
- 입장 시작 시 당일 기본 상태 `여유`를 적용한다.
- 운영 중에는 담당자가 마지막으로 저장한 당일 상태와 시각을 사용한다.
- 실제 `FestivalDay`인 날짜라면 운영 전과 운영 종료 뒤에도 담당자는 상태를 저장할 수 있다.
  공개 홈은 시간 상태를 우선해 `운영 전` 또는 `운영 종료`와 시각 숨김을 유지하며, 저장값은
  다음 운영 시간에 다시 사용한다.
- 실제 축제 운영일이 아닌 날짜에는 저장할 수 없다. 해당 날짜로 PUT하면
  `409 NOT_FESTIVAL_DAY`를 반환하고 기존 상태를 유지한다.
- 운영 전·종료에는 사용자 홈에서 업데이트 시각을 표시하지 않는다.
- KST 날짜별 운영 구간은 시작 시각을 포함하고 종료 시각을 제외한다. 종료는 다음 날
  00:00까지 허용하며, 다음 날 00:01은 허용하지 않는다.
- 관리자가 종료 시각을 현재 시각보다 앞당기면 다음 공개 조회부터 `운영 종료`를 표시한다.
  당일 안에서 종료를 연장해 현재 시각이 운영 구간에 다시 들어오면 기존 당일 혼잡도 단계와
  수정 시각을 복원한다. 운영 시간 저장은 혼잡도 단계·수정 시각을 바꾸지 않는다.
- KST 00:00에 전날 혼잡도와 수정 시각을 초기화하며 다음 운영일로 이월하지 않는다.
- 혼잡도나 만석에 따라 지도 핀·구역 색상을 변경하지 않는다.
- 장시간 변경이 없어도 별도 경고를 추가하지 않고 최종 수정 시각으로 안내한다.
- 관리자 저장 결과와 홈의 조회는 화면이 보이는 동안 15초 HTTP polling으로 반영한다.

## ADM-CROWD-002 · 날짜별 재학생존 운영 시간 조회 및 변경

총학생회 현장 운영자가 게시된 축제일의 입장 시작·종료 시각을 날짜별로 조회하고 저장한다.
관리 화면은 `/api/v2/admin/crowding/operating-hours`에서 날짜 목록을 받아온다. 목록의
각 날짜는 카탈로그 초기 시간 또는 관리자 저장값을 표시하고, `updatedAt: null`은 아직
관리자가 저장하지 않아 카탈로그 초기 시간을 사용한다는 뜻이다. 편집 중인 입력은 polling이나
재조회 응답으로 덮어쓰지 않는다.

| 화면 상태 | 동작 |
|---|---|
| 로딩 | 날짜 목록을 읽는 동안 로딩 상태를 표시하고 임의 날짜·시간을 채우지 않는다. |
| 정상 | 게시된 날짜만 날짜순으로 표시한다. 게시 날짜가 없으면 `items: []`의 빈 상태를 표시한다. |
| 저장 중 | 저장 중인 날짜만 진행 상태를 표시하고 입력한 값은 유지한다. |
| 검증 실패 | 잘못된 시간 필드와 허용 범위를 안내하고 작성한 값을 보존한다. |
| 동시 수정 충돌 | 작성한 값을 보존한 채 최신 상세 시간을 별도로 읽고 운영자가 검토한 뒤 다시 저장하게 한다. |
| KST 자정 | 날짜와 운영 상태를 다시 조회한다. 전날 혼잡도 상태 초기화와 당일의 현재 운영 시간 적용은 공개 혼잡도 규칙을 따른다. |

- 날짜마다 시작·종료 한 쌍을 따로 저장하고 저장 성공은 해당 날짜 행에 표시한다.
- 시간은 KST 기준 분 단위다. 시작은 해당 날짜 안에 있어야 하고 종료는 시작보다 뒤여야 하며
  해당 날짜 안 또는 다음 날 `00:00`일 수 있다. 다음 날 `00:00`은 종료 경계이며 운영에
  포함되지 않는다.
- 카탈로그 초기값이 새 입력 규칙에 맞지 않더라도 관리자 GET은 원본 시간을 수정·반올림하지
  않고 보여 준다. 관리자는 유효한 새 값을 입력해 해당 날짜를 저장하여 고칠 수 있다.
- `익일 00:00`은 선택할 수 있는 명시적 종료값으로 제공한다. 날짜가 바뀌는 RFC3339 값은
  다음 날짜의 `00:00:00+09:00`으로 전송한다.
- 게시에서 빠진 날짜는 목록에 나오지 않고 편집할 수 없다. 새로 게시된 날짜는 카탈로그
  초기 시간으로 시작한다. 제거 후 다시 게시한 날짜는 보존된 관리자 저장값을 사용한다.
- 시간 변경만으로 혼잡도 단계나 혼잡도 수정 시각을 바꾸지 않는다.
- 저장 후 날짜 목록·상세 시간·현재 혼잡도를 재조회한다. 충돌이나 저장 실패 때 입력값을
  보존하고 최신 서버 시간을 보여 주어 다시 검토할 수 있게 한다.

실제 UI 연동 순서와 ETag·멱등성 헤더는 [API v2 프런트 연동 안내](../../../../api-v2/FRONTEND.md#재학생존-운영-시간-관리)를 따른다.

### 실패 처리

| 상황 | 처리 |
|---|---|
| 조회 실패 | `혼잡도 정보를 불러오지 못했습니다. 다시 시도해주세요.`와 재시도 제공 |
| 저장 실패 | 기존 상태·수정 시각 유지, `변경사항을 저장하지 못했습니다. 다시 시도해주세요.` 표시 |
| 운영 시간 충돌 | 입력한 시간을 유지하고 최신 상세를 다시 조회한 뒤 사용자가 저장을 다시 결정 |
| 저장 날짜 게시 해제 | 목록·상세를 갱신하고 해당 날짜는 더 이상 편집할 수 없음을 표시 |
| 만석 확인 취소 | 저장 요청 없이 기존 상태 유지 |
