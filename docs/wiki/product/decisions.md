최신 기능 명세에서 명시적으로 `미정`, `확인 필요`, `임시 기준`, `후속 작업`으로 남긴

## 기록 방법

답변을 받으면 관련 기능 문서와 이 목록을 같은 변경에서 갱신한다. 해결된 질문은
확정 요구사항으로 옮기고 기술 구현 방식은 제품 동작과 분리해 담당 설계 문서에서
결정한다.

## 2026-09-14 v5 기준 통일

사용자가 product/admin/을 기준으로 확정했다. 관리자 운영 시간 편집·지도 혼잡도·
굿즈 수량 관리는 제외하고 한국어 공지는 외국어 번역 실패와 무관하게 먼저 게시한다.
공지 입력·번역과 상품 등록·수정의 범위는 [관리자 v5](admin/README.md)를 따른다.
구 항목 31~33(등록·수정 상세 누락, 삭제 상세 화면, 상품 관리 범위)은 v5로 해소했다.
신규 옵션 최초 상태·이미지 구성 등 미정 항목은 위 목록과 [API 기술 초안 및 통합 질문](../../../api-v2/DECISIONS.md)에서 추적한다.

- `BOOTH-001`: 부스&마켓 분류를 디자인의 여섯 개(`주점`, `부스`, `플리마켓`, `푸드트럭`,

  (`RESTROOM`, `PHOTO_BOOTH`, `SMOKING_AREA`, `TRASH_BIN`). 네 시설 밖의 장소 핀은 필터 없이
  `전체`에서만 보인다. 이전 대분류는 새 필터로 추측해 옮기지 않는다(V19).

  `예체능대학` 위치를 대체한다. `체대 → 예체능대학` 건물 표기는 그대로다.
- `HOME-001`, `ADM-CROWD-001`: 보통 안내 문구를 번역 자료·디자인에 맞춰
  `재학생존의 공간이 절반 이상 찼어요.`로 바꾼다(영어 `At least half full`, 중국어
  `已占用一半以上`). 영어·중국어 간체 번역은 [승인 번역표](translations.md)를 따른다.
- `TICKET`·`GOODS` 계좌 현재값은 catalog revision 밖의 운영 설정으로 둔다. 계좌 변경은
  HTTP 관리자 기능이 아닌 별도 DB role의 CLI만 사용한다.
- 계좌 변경은 한 명의 운영자가 dry-run, expected version, 끝 네 자리 확인, 작업자·사유·근거
  ID를 거쳐 적용한다. 빠른 현장 변경을 위해 2인 승인은 도입하지 않는다. 자격증명 유출이나
  작업 실수가 즉시 공개 계좌 변경으로 이어질 수 있으므로 trigger history, 최소 권한과
  사후 검토를 필수로 둔다.
