# 부스&마켓

[위키 홈](../README.md) · 읽는 때: 부스·주점·플리마켓 목록·상세·별·공유 변경

## BOOTH-001 · 부스&마켓

하단 내비게이션 또는 공유받은 상세 링크에서 로그인 없이 부스·주점·플리마켓 정보를
확인하고 관심 항목 저장, 상세 링크 공유와 지도 위치 확인을 이용한다. 실제 목록과
상세 정보를 출시 전에 등록하며 멋사 부스도 목록에 포함한다.

### 목록과 분류

- 분류는 디자인의 `전체 / 주점 / 부스 / 플리마켓 / 푸드트럭 / 총학생회 부스 / 프로모션 부스`이며
  최초 진입은 `전체`와 목록 맨 위다.
- `전체`는 여섯 유형을 함께 표시하고 개별 분류는 해당 유형만 표시한다.
- 분류를 바꾸면 새 목록의 맨 위로 이동한다.
- 목록 카드는 대표 사진, 이름과 위치를 표시하며 카드 전체를 선택하면 상세로 이동한다.
- 축제 3일 동안 같은 목록을 제공하고 날짜 선택 기능은 두지 않는다.
- 검색창과 검색 기능은 제공하지 않는다.

기본 정렬은 이름 가나다순이다. 별로 저장한 항목을 위에 먼저 놓고 저장 그룹과 미저장
그룹 안에서 각각 가나다순으로 정렬한다. 현재 선택한 분류 안에서 같은 규칙을 적용한다.

- 상세에서 뒤로 가면 기존 분류와 스크롤 위치를 유지한다.
- 상세에서 별 상태를 바꾸면 복귀할 때 새 저장 상태를 반영해 목록을 다시 정렬한다.
- 다른 하단 메뉴에서 돌아오면 `전체`와 목록 맨 위로 초기화하되 별 저장값은 유지한다.

### 상세 공통 구성

- 항목별 대표 사진 1장을 원본 비율로 영역에 채우고 넘치는 부분은 중앙 기준으로
  자른다. 크기는 디자인팀이 정한다.
- 이름, 분류, 운영 주체를 표시한다.
- 운영 시간, 위치와 문의 SNS 등 전달받아 등록된 정보만 표시한다.
- 정보가 없으면 값뿐 아니라 해당 제목과 영역을 함께 숨긴다.
- 하단에는 별 저장, 공유와 `지도에서 위치 보기`를 제공한다.
- 스탬프투어 참여 여부는 모든 상세 화면에서 표시하지 않는다.

### 유형별 상세

| 유형 | 표시 내용 | 제공하지 않는 내용 |
|---|---|---|
| 부스·총학생회 부스·프로모션 부스 | 소개, 체험 방법·진행 이벤트, 등록된 운영 정보 | 메뉴판 |
| 주점·푸드트럭 | 소개, 등록된 운영 정보, 메뉴명과 가격의 텍스트 목록 | 진행 이벤트 |
| 플리마켓 | 간단한 설명 중심, 전달받은 운영 주체·시간·위치·문의 | 진행 이벤트, 메뉴판 |

부스의 이벤트가 등록되지 않으면 제목과 영역을 숨긴다. 주점 메뉴는 전달받은 정보를
개발자가 직접 입력한다.

### 별 저장

모든 유형의 상세 하단에 빈 별 또는 채워진 별을 표시한다. 빈 별을 선택하면
저장하고 채워진 별로 바꾸며, 다시 선택하면 해제하고 빈 별로 바꾼다. 저장 항목은
목록 위에 우선 표시하고 같은 기기·브라우저로 다시 접속해도 상태를 유지한다.

상태 유지는 같은 기기·브라우저까지만 요구하며 다른 환경과의 동기화는 범위에 포함하지
않는다. 구체적인 저장 기술은 기능 명세에서 정하지 않는다.

### 상세 링크 공유

- 공유 버튼은 현재 상세 화면의 링크를 대상으로 한다.
- 지원 환경에서는 기기 공유창을 열어 사용자가 대상을 선택하게 한다.
- 공유창을 지원하지 않는 환경에서는 상세 링크를 복사한다.
- 공유받은 링크는 로그인 없이 해당 상세 화면으로 바로 연결한다.

### 지도 연결

`지도에서 위치 보기`를 선택하면 앱 내 [MAP-001 지도](map.md)의 해당 구역 상세 지도로
바로 이동한다. 대상 장소가 보이는 위치를 중심으로 표시하고 해당 핀을 선택한 상태로
정보 팝업을 연다. 지도 팝업의 `상세 보기`는 해당 항목의 상세 화면으로 이동한다.

### 정보 관리

개발자가 전달받은 이름, 분류, 대표 사진, 운영 주체, 소개, 운영 시간, 위치, 문의,
이벤트와 메뉴를 직접 등록·수정한다. 발전협력팀 배치도의 세 칸이 같은 부스인지 여부는
보류 상태이며, 승인 자료가 나오기 전에는 하나의 부스 또는 여러 부스로 임의 등록하지 않는다.

### 부스 계좌 송금 안내

**결제 시스템이 아니라, 부스 계좌와 금액을 안내하고 토스 송금 화면으로 연결하는 기능**이다.
백엔드는 한 명이 개발하고, 입금 확인은 웹앱 밖에서 현장 근무자가 한다.

흐름: **부스 상세 조회 → 계좌·금액 표시 → 토스 송금 화면 연결 → 사용자가 토스에서 송금 →
현장 근무자가 입금 확인**

| 구분 | 담당 범위 |
|---|---|
| Spring Boot 백엔드 | 부스별 수취 계좌 저장·조회, 기존 메뉴 가격 제공, 계좌 수정 권한과 변경 이력 |
| Next.js 프런트엔드 | 금액 표시·필요한 합계 계산, 토스 연결 버튼, 계좌·금액 복사, 연결 실패 안내 |
| 웹앱 밖 | 토스에서 실제 송금, 현장 근무자의 입금 확인 |
| 만들지 않는 것 | 주문·송금 거래 테이블, 결제 상태 API, 입금 확인 화면, 송금 결과 콜백·웹훅, 입금 내역 조회 연동 |

딥링크로 사용자 기기의 토스 화면으로 이동하므로 백엔드가 토스에 송금 실행을 요청하지 않는다.

#### 공개 조회

새 API를 만들지 않고 `GET /api/v2/spaces/{spaceId}`의 `data`에 `bankTransfer`를 더한다. 목록
`GET /api/v2/spaces`에서는 항상 `null`이다.

```json
{
  "bankTransfer": {
    "bankId": "example-bank",
    "bankDisplayName": "예시 은행",
    "accountNumber": "000000000000",
    "accountHolderName": "예시 예금주",
    "tossLinkEnabled": false
  }
}
```

| 필드 | 규칙 |
|---|---|
| `bankTransfer` | 공개할 계좌가 없으면 `null`. 이때 계좌 안내와 송금 버튼을 표시하지 않는다. |
| `bankId` | 서비스 내부 은행 식별자(소문자·숫자·하이픈). **토스 송금 링크의 은행 파라미터와 같다고 가정하지 않는다.** |
| `bankDisplayName` | 화면에 표시할 은행명 |
| `accountNumber` | 앞자리 `0`을 보존하는 문자열 |
| `accountHolderName` | 부스 담당자가 확인한 공개용 예금주명. 금융기관 실명 검증 결과로 표시하지 않는다. |
| `tossLinkEnabled` | 토스 연결 노출 여부. 실기기 검증 전에는 `false`이고 계좌 복사는 항상 별도로 제공한다. |

**금액은 계좌 객체에 저장하지 않는다.** 같은 부스에서도 선택한 메뉴와 수량에 따라 달라지므로
계좌와 메뉴 가격을 분리한다.

#### 계좌 입력과 이력

v2에는 부스 등록·수정 HTTP API가 없다(부스 콘텐츠는 catalog manifest로 게시한다). 부스 계좌는
catalog가 아닌 **운영 계좌 설정의 `SPACE` 용도**로 저장하고 기존 계좌 CLI로만 바꾼다. 부스당
공개 계좌 1개이며, 변경은 trigger history에 남고 게시·재시작 없이 다음 요청부터 반영된다.
catalog export·publish role은 계좌를 읽지 못한다. 절차는
[계좌 운영 설정](../engineering/operational-account-settings.md)을 따른다.

#### 합계 계산

서버가 주문 금액을 확정하거나 상품 지급을 승인하지 않으므로 합계는 **송금 편의를 위한 안내값**이다.
화면의 금액이나 토스 버튼 클릭을 입금 증거로 쓰지 않는다.

| 사용 방식 | 금액 처리 |
|---|---|
| 메뉴 하나 송금 | 메뉴 가격 사용 |
| 같은 부스의 여러 메뉴·수량 | 프런트에서 `단가 × 수량` 합산 |
| 현장에서 금액을 정하는 경우 | 현장 안내 금액 입력 UI 또는 계좌 복사로 안내 |
| 다른 부스의 메뉴 | 하나의 합계로 묶어 한 계좌에 송금하지 않음 |

가격이 없는 메뉴(무료·가격 미정·현장 문의)는 `0원`으로 계산하지 않고 자동 합계에서 빼거나 현장
확인으로 안내한다.

#### 줄여도 남기는 검증

| 항목 | 확인 내용 |
|---|---|
| 계좌 정확성 | 등록된 은행·계좌·예금주가 부스 담당자가 확인한 정보와 같은지 |
| 계좌 수정과 캐시 | 변경 뒤 이전 계좌가 표시되거나 송금 링크에 쓰이지 않는지. 상세 응답은 `Cache-Control: no-store`이고 계좌를 매 요청 DB에서 읽는다. |
| 금액 처리 | 수량의 소수·음수·빈 입력, 가격 미정 항목, 다른 부스 메뉴 혼합 |
| 앱 연결 실패 | 토스 미설치·실행 취소·인앱 브라우저 제한에서 계좌·금액 복사가 되는지 |

토스 연결은 백엔드 테스트만으로 완료로 보지 않고 최소 iPhone Safari와 Android Chrome에서
확인한다. 외부 웹에서 계좌·금액을 전달하는 토스 송금 파라미터의 공식 명세는 확보하지 못했으므로
송금 URL은 **실기기 검증과 지원 확인이 필요한 후보**다. 토스 연결이 검증되지 않아도 계좌 안내·복사는
제공하며, 토스 연결은 검증을 통과한 계좌에만 `tossLinkEnabled=true`로 켠다. 참고:
[딥링크](https://docs.tosspayments.com/resources/glossary/deep-link),
[딥링크 실전 사용](https://docs.tosspayments.com/blog/how-to-use-deep-links).

### 빈 상태와 오류

| 상황 | 처리 |
|---|---|
| 목록에 등록된 항목 없음 | `등록된 정보가 없어요.` |
| 목록·상세 조회 실패 | `정보를 불러오지 못했어요.`와 `다시 시도` |
| 재시도 성공 | 정상 목록 또는 상세 표시 |

`다시 시도`를 선택하면 조회에 실패한 정보를 다시 요청한다.
