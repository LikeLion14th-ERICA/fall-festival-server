# 스탬프투어

## STAMP-001 · 스탬프투어 참여 및 상품 수령

로그인 없이 여러 부스를 체험하고 스탬프를 모아 멋사 부스에서 몬스터 상품을 받는
기능이다. [HOME-006](home.md) 또는 휴대폰 기본 카메라로 스탬프투어 QR을 스캔해
진입한다.

기본 흐름은 `START 선택 → QR로 4개 적립 → 멋사 부스 방문 → 담당자가 수령 인증 코드를
입력하고 확인 → 몬스터 수령`이다. 하루 최대 4개를 적립하고 상품은 하루 1회만 받는다.

### 시작 화면

시작 화면에는 축제 정보, 스탬프투어 제목, 실제 행사 기간, START 버튼, 참여 방법,
지급·초기화·소진 조건과 몬스터 협찬 정보를 표시한다.

- START를 선택하면 서버가 이 브라우저에 익명 참여자 쿠키를 발급하고(`POST /api/v2/stamp-participants`)
  수집 화면으로 이동한다. 이름·전화번호 같은 개인정보와 계정·복구 수단은 없다.
- START만으로 스탬프를 적립하지 않는다. 첫 스탬프도 멋사 부스의 QR을 스캔해야 한다.
- `상품은 하루 1회 수령 가능`, 매일 밤 12시 초기화와 당일 수령 필요,
  `상품은 준비 수량 소진 시 지급이 종료됩니다`를 안내한다.
- 참여 순서는 멋사 부스에서 시작 QR로 1개 적립, 다른 부스 체험 뒤 운영자가 보여 주는
  QR 스캔, 총 4개 뒤 멋사 부스에서 상품 수령이다.
- `부스 돌고 몬스터 받자!`는 제안 문구이며 최종 디자인 문구가 아니다.

실제 행사 기간과 상품 수령 운영 시간은 확정 자료를 반영한다.

### 수집 화면과 버튼 상태

동일한 디자인의 스탬프 4칸과 `현재 적립 개수 / 4`를 표시한다. 유효 QR을 인식할
때마다 다음 빈칸에 1개를 표시하며 별도 성공 문구나 팝업은 제공하지 않는다.

| 당일 상태 | `QR 찍기` | 상품 버튼 |
|---|---|---|
| 0~3개·미수령 | 활성, 앱 내부 카메라 실행 | `상품 받으러 가기` 비활성 |
| 4개·미수령 | 비활성, 선택 동작 없음 | `상품 받으러 가기` 활성 |
| 4개·수령 완료 | 비활성 유지 | `오늘 상품 수령 완료` 비활성 |

상품 수령 뒤에도 스탬프를 차감하지 않지만 추가 적립과 추가 상품 수령은 불가능하다.
4칸이 모두 채워진 스탬프판과 `상품 수령 완료` 상태는 계속 표시한다.

### QR과 적립 규칙 (2026-09-22 변경)

- 참여 부스마다 **고유한 QR**을 쓴다. QR 링크는
  `https://festival.likelionerica.com/stamps?b=<부스 토큰>`이며 토큰은 부스별 128비트 난수다.
  catalog에는 토큰의 SHA-256만 저장하고 원문은 QR 링크에만 있다([부스 스탬프 QR](../../../ops/stamp/README.md)).
- 부스 운영자가 체험 완료 후 참여자에게 QR을 보여 준다.
- 서버가 참여자(익명 쿠키)별로 적립을 기록한다. 축제일(Asia/Seoul) 하루에 **같은 부스는 1회**,
  합계 4개까지 적립하고, 같은 부스를 다시 찍으면 `이 부스의 스탬프는 오늘 이미 받았어요`로 거절한다.
- 4개에 도달하거나 상품을 받은 뒤에는 추가 적립하지 않는다.
- 부스별 토큰은 축제 기간 전체용 1개 또는 축제일별 1개로 만들 수 있다. 날짜별 토큰은 촬영·공유된
  QR을 그날만 유효하게 한다.
- 브라우저 데이터를 지우면 새 빈 스탬프판으로 다시 시작한다. 기존 스탬프 복구는 제공하지 않는다.
  서로 다른 부스 4곳을 모아야 한다는 규칙은 새 스탬프판에도 그대로 적용된다.
- 사용자 계정, 사용자별 QR, QR 서명과 스탬프 복구(passkey·복구 코드)는 이 기능에 추가하지 않는다.

### QR 스캔 경로와 예외

| 경로·상황 | 처리 |
|---|---|
| 앱 내부 | `QR 찍기` → 카메라 허용 → 인식·1개 적립 → 카메라 종료 → 수집 화면 복귀 |
| 휴대폰 기본 카메라·START 전 | 부스 QR 링크를 열면 적립 API가 `STAMP_NOT_STARTED`이므로 시작 화면으로 이동, 스탬프 적립 없음 |
| 휴대폰 기본 카메라·START 후 | 부스 QR 링크 진입 → 적립 처리 → 수집 화면 연결 |
| 같은 부스 QR을 같은 날 다시 인식 | 적립 없이 `이 부스의 스탬프는 오늘 이미 받았어요` 표시 |
| 카메라 미허용 | 적립 없이 기존 화면 유지, `QR을 찍으려면 카메라 접근을 허용해 주세요` 표시 |
| 스탬프투어 외 QR | 적립 없이 `스탬프투어 QR이 아니에요` 표시, 카메라를 유지해 재스캔 허용 |

기본 안내 경로는 앱 내부 `QR 찍기`다. 서로 다른 브라우저의 기록은 자동 합산하지
않는다. START 전에 기본 카메라로 부스 QR 링크에 직접 들어오면 시작 화면으로 이동하며,
자동으로 참여를 시작하거나 스탬프를 적립하지 않는다. 같은 브라우저에서 START를 마친
뒤 기본 카메라로 진입한 경우에만 적립 처리 뒤 수집 화면으로 연결한다.

### 상품 수령

스탬프 4개를 모으고 아직 받지 않은 사용자가 `상품 받으러 가기`를 선택하면 수집
화면 위에 작은 안내 창을 연다.

- `이 화면을 멋사 부스 담당자에게 보여주세요.`를 표시한다.
- 안내 창에는 `상품 수령` 버튼을 두지 않는다. `수령 인증 코드` 입력칸과 `확인` 버튼을
  제공한다.
- 멋사 부스 담당자가 현장에서 4칸 완료와 지급 가능 여부를 확인한 뒤 사용자 휴대폰의
  입력칸에 수령 인증 코드를 직접 입력한다. 코드는 **6자리 숫자**이며 입력칸은 숫자 키패드로
  6자리만 받는다. 사용자가 코드를 입력하거나 공유받는 흐름은
  제공하지 않는다.
- `확인`은 코드만 `POST /api/v2/stamp-receipt-verifications`로 전송한다. 인증 코드는
  브라우저 저장값·화면 안내·`StampGuide` 응답에 넣지 않으며, 제출 뒤 입력칸에서 지운다.
- 서버는 코드가 맞고 이 브라우저의 오늘 스탬프가 4개이며 아직 받지 않았을 때만
  `verified: true`를 돌려주고 오늘 수령을 기록한다. 스탬프판은 하루 1회만 상품을 받는다.
  응답 뒤 창을 닫고 상품 버튼을 비활성화한다.
- 코드가 틀리거나 요청에 실패하면 수령 상태를 바꾸지 않고 안내 창을 유지한다. 코드 오류는
  `코드를 확인해 주세요`만 표시하고, `확인`을 누르는 동안에는 중복 제출하지 않는다.
- 안내 바깥을 선택하면 처리 없이 닫고, 미수령 상태에서는 다시 열 수 있다.
- 앱에는 실시간 상품 소진 표시, 관리자 소진 설정과 소진에 따른 버튼 변경을 제공하지
  않는다. 소진 여부는 현장 부스에서 안내한다.

### 당일 기록과 초기화

같은 기기·브라우저(익명 참여자 쿠키)에서는 참여 여부, 적립한 부스와 수령 상태를 서버가
유지한다(`GET /api/v2/stamp-card`). 수령 상태는 현장 담당자의 코드 인증 성공 때만 기록한다.
참여 쿠키가 있으면 시작 화면을 생략한다.

한국 시간 00:00에 시작 기록·스탬프 개수·수령 상태를 각각 시작 전·0개·미수령으로
초기화한다. 미사용 스탬프는 이월하지 않으며 다음 날 4개를 다시 모으면 상품을 하루
1회 받을 수 있다. 다음 진입에는 시작 화면을 표시하고 START를 선택한 뒤 0개 수집
화면에서 `QR 찍기`를 활성화하고 `상품 받으러 가기`를 비활성화한다.
