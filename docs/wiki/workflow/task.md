# 작업 절차와 워크트리

[위키 홈](../README.md) · 읽는 때: 작업 시작·병렬 격리·통합·작업 종료

1. 최초 숙지는 [시작 안내](../START_HERE.md)를 따른다. 이후 작업은 루트 AGENTS.md의
   공통 규칙과 [작업별 읽기 표](../README.md)에서 해당하는 페이지만 읽는다. 관련 API 절,
   Figma node와 하위 운영 문서는 변경 영향이 있을 때 읽는다.
2. 요구사항을 `확정 / 자료 대기 / 협의·보류 / 후순위 / 제안` 중 하나로 분류한다.
3. 학교 용어 또는 상위·하위 자료 충돌을 발견하면 추측하지 말고 질문한다.
4. 한 PR에는 하나의 목적 또는 하나의 기능 도메인만 담는다.
5. 새 추상화를 만들기 전에 기존 컴포넌트·토큰·패턴을 재사용한다.
6. 기능 테스트뿐 아니라 계약, 접근성, 보안, 성능, 관측성, 캐시 무효화와 복구 영향을
   변경 위험에 비례해 검증한다.
7. 관련 테스트, 타입 검사, 린트, 빌드를 실행하고 결과와 미실행 사유를 PR에 기록한다.
8. 저장소에 선언된 명령만 실행한다. toolchain이나 배포 절차가 바뀌면 실제 명령과
   운영 runbook을 같은 변경에서 갱신한다.
9. 둘 이상의 에이전트가 병렬로 파일을 수정할 때는 같은 checkout을 공유하지 않는다.
   각 에이전트에 최신 `main`에서 만든 전용 branch와 linked worktree를 배정하고, 모든
   명령과 파일 변경은 배정된 worktree 안에서만 수행한다.
10. 루트 checkout은 통합과 검증 용도로 유지한다. 에이전트 작업을 시작하기 전에 루트와
    대상 worktree가 clean인지 확인하고, 서로 다른 작업이 같은 branch를 공유하지 않게 한다.
11. 병렬 결과는 각 worktree에서 관련 검증과 commit을 마친 뒤 review 가능한 단위로
    `main`에 병합한다. 충돌은 통합 checkout에서 해결하되 다른 에이전트의 변경을 임의로
    버리지 않는다.
12. 병합이 끝난 worktree와 작업 branch는 상태를 확인한 뒤 제거한다. `.worktrees/`는
    로컬 격리 공간이며 commit하지 않는다.
