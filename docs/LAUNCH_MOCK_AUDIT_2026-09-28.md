# 출시 전 목업 데이터 점검 (2026-09-28)

범위: 공개 API `https://api-festival.likelionerica.com`의 읽기 전용 응답과
`https://festival.likelionerica.com`에 배포된 주요 화면 HTML·JavaScript 번들.
운영 DB와 관리자 전용 목록은 조회하지 않았다.
관리자 웹 `https://admin-festival.likelionerica.com`은 진입 페이지가 응답하지만,
인증 세션이 없어 공지·상품의 숨김 항목이나 변경 권한은 확인하지 못했다.

## 현재 공개 상태

| 영역 | 확인 결과 | 필요한 조치 |
| --- | --- | --- |
| 게시 카탈로그 | 공개 응답의 `meta.revision`은 6. 부스 20개, 지도 4개에 `[목]`, `mock-` ID, `placehold.co` 이미지가 남아 있다. | 실제 운영 manifest를 검증·게시한 뒤 백엔드를 재시작한다. |
| 홈 설정 | 축제명은 `한양문화제 동심`이고, 학교 공지·FAQ 링크는 `[목]` 및 `example.invalid`를 사용한다. | 확인된 공식 링크와 행사명 `제1회 한양문화제 동심`을 운영 설정에 반영한다. |
| 공연·타임테이블 | 공개 공연 정보가 mock 아티스트·공연 ID와 자리 표시 이미지를 사용한다. | 공연 담당 팀의 운영 데이터 작업과 합친다. |
| 스탬프 안내 | 제목·설명·상품 문구가 `[목]`이다. QR 값 `https://festival.likelionerica.com/stamps`는 운영 초안과 같다. | 실제 manifest의 안내로 교체한다. |

| 공지 | 현재 노출 공지 1개가 `테스트` / `테스트입니다`이다. | 관리자에서 테스트 공지를 비공개 또는 삭제하고 실제 공지를 등록한다. |
| 굿즈 | 공개 상품 7개에 위의 목업 문자열은 없었다. 첫 상품의 결제 안내에는 계좌가 없다. | 승인된 굿즈 입금 계좌를 확인·설정한다. 관리자에 숨은 예전 mock 상품이 있는지는 별도 확인한다. |
| 혼잡도 | 응답에 명시적 목업 문자열은 없다. 기본 운영 상태는 게시 카탈로그의 시간에 영향을 받을 수 있다. | 실제 축제일 운영 시간을 등록한 뒤 상태를 다시 확인한다. |

## 프런트엔드에서 따로 발견한 목업

주요 화면 10개의 HTML에는 목업 문자열이 없었으나, 배포된 JavaScript 번들
24개 중 4개에 `mock-` ID가 남아 있다. 부스 목록 번들은 API 목록에
로컬 부스 데이터를 합치고 API 실패 시 로컬 데이터를 반환한다. 따라서 **백엔드만
실데이터로 바꿔도 프런트에서 목업 부스가 계속 보일 수 있다.** 공연 번들에도
`mock-artist-wish` 등에 의존하는 표시·정렬 로직이 있다. 프런트 저장소
`LikeLion14th-ERICA/fall-festival-web`에는 현재 접근할 수 없어 배포 번들에서만
확인했다. 프런트 담당자는 실데이터 게시 전에 부스 목록의 로컬 병합·실패
fallback을 제거하고, 공연 담당자는 새 아티스트 ID에 맞는 화면 동작을 확인해야 한다.

## 이 저장소의 운영 초안 상태

`ops/catalog/hanyang-2026/catalog-draft.json`에는 실제 행사 공간 68곳,
아티스트 16팀, 공연 11건이 들어 있다. 사용자 제공 운영표로 확인된
주점 4곳의 소개와 축제일 운영 시간
(매일 09:00~익일 00:00)을
이번 점검에서 반영했다. 주점 메뉴 13행은 프런트엔드 담당 범위라 초안에서 제외했고,
푸드트럭 메뉴 24행은 남겼다. 공연 시각은 별도 담당
팀이 작업 중이므로 이 변경에 포함하지 않았다. `OperationalCatalogDraftTest`
2개가 통과했으며, 초안은 아직 import 불가 상태다.

공간·아티스트 이미지는 프런트엔드 담당 범위로 정해졌다. 이 저장소에는
이미지 3개 필드를 함께 비울 수 있는 V33 migration, 검증·조회, `image: null`
공개 API 계약을 반영했다. 아직 원격 서버에는 배포하지 않았다. 공연 시각은 별도
담당 팀 작업이다. 지도 이미지·핀도 프런트엔드에서
관리하기로 정해졌으며, 백엔드 운영 초안의 지도 목록은 비어 있다.
PostgreSQL import·publish·조회·export를 포함한 집중 Java 테스트 79개와
API 계약 테스트 461개가 통과했다.
티켓 송금 가능 시간,
반입 금지 물품, 공식 FAQ·학교 공지 링크, 굿즈 입금 계좌도 출시 전 확인이 필요하다.
추가로 전달된 Notion export에는 배치도·홍보 포스터·콘테스트 팀 사진이 있다.
예를 들어 `피크닉존_1(1).png`는 행사명·날짜가 크게 박힌 포스터이고
`프로모션_배치도.png`는 칸별 배치표다. 이것만으로 공간 68곳의 카드 사진이나
메인 아티스트 8팀 사진을 채울 수는 없다. 파일명이나 포스터를 임의의 카드
이미지 URL로 사용하지 않는다.

`확정 데이터` 폴더의 한글·영어·중국어 Markdown 원문은 모두 프로모션,
주점, 플리마켓, 공연, 푸드트럭, 이벤트의 같은 10개 섹션을 담고 있다.
운영 manifest에는 현재 공간 68곳·아티스트 16팀·공연 11건의 한국어 번역만 있고,
영어·중국어는 티켓·스탬프 안내에만 들어 있다. 원문 번역을 그대로 공개하려면
개별 행을 ID에 매핑하고 locale 전체 공개 조건을 검증해야 한다.

실데이터 게시 순서는 프런트의 `image: null` 처리·목업 병합 제거 확인 →
원격 DB 읽기 전용 사전 점검 → V33 migration → 공연팀 자료 병합 →
catalog import/validate/publish → 백엔드 재시작 → 공개 API 확인이다.
공지·굿즈·계좌는 카탈로그와 별도로 관리자 API 또는 운영 CLI에서 정리한다.
현재 실서비스 DB 변경은 하지 않았다.

개발용 목업 생성기와 fixture(`dev/catalog`, `dev/admin-mock`)는 개발 자료로
남아 있다. `src/main`에는 해당 문구를 공개 응답에 고정한 코드가 없으며,
현재 노출은 게시된 목업 카탈로그·동적 관리자 데이터·배포된 프런트 번들에서 온다.
